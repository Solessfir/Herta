# Rendering

See the [Milestone 4.5 completion report](Milestone45.md) for verified platforms, playground captures, measured budgets, and remaining limitations.

The editor renders authored levels through a native HDR PBR pipeline beneath the docked panels. The camera uses a 65-degree vertical perspective field of view. Viewport layout and camera input are resolved before rendering, so resizing uses the current frame's aspect ratio. Render-target size limits scale both dimensions together. The depth-tested meter grid uses subdued major lines and distance fading. Saved workspace layouts remain intact.

## Ownership

- `RHI` owns resource descriptors, shared GPU handles, the graphics device contract, and the versioned cooked shader format. Calls belong to one render thread; all resource handles must be released before the owning presentation device.
- `NvrhiVulkan` privately maps those operations to NVRHI. Three independent command contexts retain recorded resources and upload storage until their graphics-queue submission serial completes. Cancelling a recording releases CPU commands without submitting GPU work.
- `RenderGraph` validates declared reads/writes, derives resource hazards, orders passes deterministically, and scopes transient ownership to first and last use. RHI retention extends GPU lifetimes past graph execution. This first graph runs on the graphics queue; physical aliasing and asynchronous compute are deferred.
- `Renderer` owns GPU meshes/materials, HDR and display targets, shadows, environment lighting, fog, tone mapping, SMAA, and grid/debug passes. It owns no content: the editor supplies view/projection, model matrices, material-slot overrides, lights, environment settings, and overlays. Null meshes, such as ones still loading, are skipped.
- `FRenderMesh` is the GPU copy of a cooked model: vertex/index buffers, imported material defaults, mip-mapped textures, sections, and bounds. `FRenderMaterial` owns editable parameters and texture handles separately. Instances sharing one GPU mesh and material-slot overrides batch into indexed instanced draws. Recorded frames retain handles, so replacement never waits for the whole GPU.
- Each frame culls world-space mesh bounds against the camera, every shadow view, and the visible selection. Local shadow views also cull against the light's range, because their projections have no far plane. Culled instances for all views are stored back to back in one instance buffer that grows by powers of two. Meshes with per-frame vertex updates, such as soft bodies, are never culled, because they can deform beyond their cooked bounds.
- `EditorCore` owns the viewport camera math. `EditorFramework` owns input routing, the preview transform, and its private im3d context; it copies im3d output into Herta debug primitives before rendering.

The world grid is a two-triangle GPU procedural pass after opaque geometry, with reversed-Z depth testing and no depth writes. `WorldGrid.slang` evaluates anti-aliased 1 m minor and 5 m major lines, fading from 50 m to 200 m around the camera. Only four projected vertices are uploaded per frame; the grid does not enter the CPU debug-line expansion path.

Uploads use NVRHI staging with a 64 MiB per-recording limit, exposed as `MaximumUploadBytesPerRecording`. `FRenderMesh::Create` submits and begins a new recording whenever the next write would exceed it, so a 4096x4096 texture with its mips uploads across several recordings. Textures are uploaded one mip level at a time and cannot be sampled until every level has been written. Frame reuse waits only for that context's submission, rather than waiting for the entire device every frame. Readback is an explicitly blocking diagnostic operation.

Draw uniforms use NVRHI volatile constant buffers, which suballocate each write from the upload ring. Ordinary buffer writes would end the render pass and add a barrier before every draw. Each recording creates a framebuffer once per target pair and a binding set once per pipeline layout and resource combination, then reuses them for every draw.

VSync is enabled by default and can be toggled from the application menu. The change is applied between frames by recreating the main and detached viewport swapchains with FIFO or the best available non-VSync present mode.

The scene uses column-major matrices, a +Z-forward camera, counter-clockwise front faces, infinite-far reversed-Z projection, depth clear `0`, and `GreaterOrEqual` depth testing. NVRHI supplies Vulkan's viewport Y inversion; shaders do not flip Y again.

Meshes carry cooked normals and tangents with explicit handedness. Surface lighting uses metallic-roughness GGX PBR, authored lights, and filtered environment lighting. The instanced vertex stream carries object-to-clip and object-to-view matrices (128 bytes per object). Single draws retain the 128-byte push-constant ABI. Unlit new levels and asset thumbnails have a studio preview; authored lighting replaces it.

Color textures use sRGB sampling; numerical maps use Linear. Scene lighting and fog accumulate into RGBA16F HDR targets. Exposure and GT7 tone mapping produce the sRGB display target. ToolUI samples the completed image through an UNORM view so UI composition does not decode it twice.

## Viewport interaction

Use RMB with WASD and QE for fly navigation, Alt+LMB to orbit, MMB to pan, and the wheel to dolly. While flying, the wheel adjusts movement speed and Shift accelerates movement. F focuses the selection. The viewport toolbar exposes translation, rotation, scale, local/world axes, and snapping.

Camera and gizmo drags start only over the viewport image. They keep ownership through the drag and release it on focus loss or cancellation, so other editor widgets cannot drive the camera. Grid, axes, and bounds use level depth; transform handles draw as an overlay. Level owns authored entities; EditorFramework adapts their transforms to the viewport and records grouped authoring transactions for undo/redo.

Click a mesh or editor marker to select its entity; click empty viewport space to deselect. Ctrl/Shift-click toggles additional entities, and dragging from empty space box-selects projected bounds. Selection shows transform handles and a two-pixel outline of the rendered meshes, including alpha cutouts, dimmed where other geometry hides them. The outline rasterizes the selected meshes into a selection depth target with the depth-only shadow pipeline and composites after SMAA, shading only the selection's projected screen bounds. Camera navigation and gizmo clicks preserve selection. Light and environment components have typed editor guides, including selected ranges and emitter shapes. G hides authoring overlays without hiding the optional camera coordinates or entering Play.

Details and gizmos edit world-space location in meters, XYZ Euler rotation in degrees, and positive per-axis scale; levels store parent-local transforms. Compact RGB-marked fields omit axis labels and trailing zeros. Changed properties expose revert arrows. Locking scale preserves all three starting proportions and rejects edits outside the positive supported range. Search filters properties and components. Multi-selection changes are grouped into undoable gestures and saved with the level. With no selection the panel displays a selection prompt.

Translation and scale use small colored plane handles. Scale plane handles change two local axes together while preserving their starting ratio. During dragging, translation displays meters, scale displays multipliers relative to the starting scale, and rotation displays the signed applied angle with a swept sector. Dotted guides replace full-length axis lines; releasing or cancelling hides the feedback.

Q hides the transform gizmo without deselecting; W/E/R select move/rotate/scale and show it again. L switches local/world axes while the viewport owns keyboard focus. These shortcuts do not override RMB flight controls. Escape cancels a transform drag and restores its starting transform. Alt+RMB also dollies. RMB navigation hides the pointer. Changing the flight speed with the mouse wheel or the Camera speed slider shows it, including Shift acceleration, for 1.5 s after the last change. The toolbar's Grid (m) field sets the translation snap interval. Navigation uses ordinary pointer motion, so a continuous drag is bounded by the desktop edge; Play captures the pointer for relative look.

im3d is pinned under `External/im3d` and is private to EditorFramework. The renderer accepts Herta-owned points, lines, and triangles. Pixel-width lines and points expand to triangles without requiring geometry shaders or native wide-line support.

## Visual authoring

[Materials](Materials.md) describes editable PBR assets, mesh slots, and project Slang iteration. Directional, Sky, Point, Spot, and Rect lights are independently optional level components, available through placement and Add Component. Details exposes linear color or temperature, physical intensity, range, shadow biases, spot cones, and rectangle dimensions. Directional range sets shadow distance, 60 m by default, and the last cascade fades out over its final 15%.

The renderer admits at most 256 enabled lights in stable entity order. Shadows use one 4096x5120 reversed-Z Depth32 atlas (80 MB) with at most 16 views. The first shadow-casting Directional light owns four 2048x2048 cascades in the top 4096x4096; further directional lights cast no shadows. Point (six faces), Spot, and Rect (one each) share sixteen 512x512 tiles in the strip below. Admission is whole-light, so insufficient space disables that light's shadows rather than rendering incomplete cube faces. Cascade normal offset scales with each cascade's world texel size. Viewport settings exposes Off, Hard, and Soft shadows and the budgets; both use bilinear-weighted PCF over 2x2 and 4x4 texels, read with one and four gathers. The depth prepass draws visible opaque and cutout geometry with the PBR vertex shaders and the masked depth shader, then PBR shading tests for equal depth without writing it, so each pixel runs the lighting shader once; without it, hidden surfaces drawn first measured about six shaded samples per pixel. Custom material shaders may move vertices, so they skip the prepass and write their own depth. Small or alpha-tested geometry such as foliage can use the same path: a cutout depth pass discards twice and small pieces occlude little, so engines often keep only large occluders in the prepass (Unreal's `r.EarlyZPass` 1). Add that filter, by cutout material or screen size, once dense vegetation exists to measure it. Surfaces skip shadow filtering for lights that contribute nothing, and Rect lighting skips pixels behind the emitter or out of range. Rect surface lighting uses linearly transformed cosines (Heitz et al. 2016) with the published GGX fit in [External/ltc](../External/ltc/UPSTREAM.md): two 64x64 tables turn diffuse and specular into closed-form clamped-cosine integrals over the emitter quad, within a few percent of brute-force GGX, so glossy surfaces show a solid rectangular highlight. Rect range is measured from the emitter's surface, and Rect shadows are a single center projection, not soft area shadows. There is no light baking or dynamic GI.

Sky Light filters a cooked HDR environment or the procedural atmosphere into diffuse irradiance and roughness-dependent GGX specular mips. Filtering runs on background tasks and keeps the previous environment while updating. Visibility and ambient strength are independent. Sky Atmosphere links a directional sun and ray-marches single-scattering Rayleigh, Mie, and ozone from sea level, using the authored scattering scales, anisotropy, planet radius, and atmosphere height. Multiple scattering uses Hillaire's 2020 transfer table (Psi_ms): a 32x32 RGBA32F table over sun cosine and altitude, integrating second-order isotropic scattering over 64 directions with Earth's 0.3 ground albedo and amplifying it by 1 / (1 - f_ms). The CPU builds it only when the scattering scales, planet radius, or atmosphere height change; moving the sun reuses it. With an atmosphere, the directional sun is authored above the air (about 128,000 lx for the real sun). Surfaces and fog receive it multiplied by the transmittance along its direction, so sunsets redden, and once the sun sets direct light stops and the sky falls dark. The visible sun disc has the sun's real luminance, its illuminance over a 0.27 degree radius (about 600 million cd/m2), and clips at the half-float scene-color maximum. Image-based lighting leaves the disc out because the directional light already provides it. Covered interiors still receive unoccluded sky light, because there is no sky occlusion or global illumination, so realistic indoor lamps only read once the sky is dark. Below the horizon, each direction shows the sky's horizon colour for its azimuth, darkening towards the nadir, so an open level reads as distant haze instead of a flat ground plane without repeating the sky's gradient or sunrise glow upside down. Environment filtering bakes the same model into a 128x64 table once per change, then filters it like an authored environment map. Clouds, aerial perspective, and sky occlusion are not implemented. Bloom is not implemented either; when it is, it should use the same dual-filter Kawase downsample/upsample pyramid as the editor glass blur, running on HDR scene color before tone mapping.

Height Fog integrates density, albedo, and anisotropy along view rays to opaque depth. Density is constant below the fog entity's height and falls off exponentially above it, so a void beneath the level is not filled with opaque fog. Ambient in-scattering uses the sky's mean radiance, estimated from the zenith and nadir irradiance. Volumetric mode adds supported lights and shadow visibility with 16/32/64 steps. Fog always uses the Hard 2x2 shadow filter, since the dither and upsample already soften it and Soft filtering would quadruple the loads at every step. The fog target is quarter resolution, capped at 512 pixels per dimension. Each pixel offsets its samples along the ray by interleaved gradient noise, so shadow shafts dither instead of stepping into slabs, and tone mapping averages that dither with a depth-aware 3x3 Gaussian upsample while compositing fog, so there is no separate full-resolution composite target. Exposure metering applies fog to its own taps. Disabling volumetric mode keeps height fog at eight integration steps. There is no temporal history, so cuts and resize need no history reset; very long rays at Low quality can still show fine grain.

The pass order is shadow atlas, light clusters, HDR sky, a depth prepass (split around the depth hierarchy with occlusion culling), ambient occlusion, PBR geometry, optional motion vectors, quarter-resolution fog, exposure metering, the tone-map LUT, fog composite with exposure/tone mapping, SMAA 1x, then grid/debug overlays and ToolUI. Exposure is photographic EV100: the tone mapper scales scene luminance by 1 / (1.2 * 2^EV100), the saturation-based convention from Lagarde and de Rousiers. The editor derives EV100 from the viewport's physical camera aperture, shutter, and ISO, or meters it automatically. Automatic exposure stays on the GPU: a pass samples the HDR scene into a 32x32 grid of centre-weighted log luminance, a 64x1 pass builds a 64-bin histogram with one pixel per bin, and a one-pixel pass averages its 10th to 90th percentile so a few highlights or deep shadows cannot swing it, converts that to reflected-light EV100 (log2(L) + 3) with a one-stop brighter bias, as Unreal does by default, so sunlit scenes with bright sky meter near "sunny 16", clamps it to EV100 1 to 18 so night scenes stop at a night-street exposure, and eases towards it with rates of 3/s brightening and 1.5/s darkening. Tone mapping reads the resulting one-pixel exposure, so nothing is read back to the CPU. The tone mapper is a port of Polyphony Digital's GT7 operator ([reference](../External/gt7/UPSTREAM.md)): exposed 1.0 becomes its 250 cd/m2 SDR paper white, the GT curve maps each Rec.2020 channel, and the result blends 60% towards a version that keeps the original ICtCp hue and fades chroma to white near the peak. Midtones stay nearly linear and saturated highlights keep their hue instead of skewing. Each frame bakes the operator for the current display into a 64x64x64 RGBA16F LUT over exposed log2 values from 2^-12 to 2^8, unwrapped into a 4096x64 target; the full-screen pass reads it with two filtered taps. 32 steps put saturated highlights more than 20 sRGB levels off, because the hue-preserving fade bends sharply; 64 keeps the 99.9th percentile within 3 levels. SDR output divides by paper white; HDR10 output reuses the same curve with the display peak and writes a half-float display target relative to paper white, which ToolUI encodes; see [HdrOutput.md](HdrOutput.md). The three automatic exposure passes together cost about 0.07 ms. Viewport settings provides the camera, the quality tier, SMAA Off/Low/Medium/High/Ultra, shadow quality, ambient occlusion, and occlusion culling; the Performance panel reports GPU pass timings and render-target memory. Defaults are the "sunny 16" EV100 15 (f/16, 1/125 s, ISO 100), SMAA High, and Soft PCF shadows. SMAA uses the [unmodified reference implementation and lookup data](../External/SmaaUpstream.md). It does not resolve temporal subpixel shimmer, and requires no motion vectors or history. Edge detection and blending weights run as compute, following Jimenez's Filmic SMAA (SIGGRAPH 2016): the edge pass writes edges for every pixel and appends each edge pixel to a list, reserving slots with one atomic per wave and counting 64-pixel groups as it goes, so the weight pass is an indirect dispatch over the list with no setup pass. The list holds one uint per pixel, 23 MB at 3200x1809. Neighborhood blending stays a full-screen pass because it writes the sRGB display target. The full-screen edge and weight passes remain as the reference; `--renderer-test` requires the compute path to match them within one 8-bit level. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, the weight pass dropped from 0.14 to 0.03 ms and edges stayed at 0.17 ms, taking SMAA High from 0.40 to 0.28 ms. Edge detection reads nine colors per pixel without shared memory; caching them per group is the next step if it matters.

Lights are culled into clusters: 64-pixel screen tiles by 24 exponential depth slices from 0.1 to 500 m, the last slice reaching to infinity. Light data lives in a storage buffer that shaders read as a `StructuredBuffer` through `VisualLights.slangh`, so only the camera, sky, fog, shadow, and material fields remain in the per-draw uniform block, and shaders that need just the sun read `Visual.SunDirection` and `Visual.SunRadiance`. A compute pass gives each cluster eight uints, one bit per light, set for the lights whose bounding sphere touches the cluster's view-space box. Directional lights are always set, sky lights never; spot and rect lights use their range sphere, rect lights grown by half their diagonal because their range starts at the emitter's surface. The PBR and volumetric fog shaders look up their cluster from the pixel and view depth and loop over its set bits only, with the first 32 lights in their own loop. Renderers without the cluster shader, such as thumbnails, bind one all-set mask. With the Sandbox's then 32-light budget filled by 27 extra unshadowed 800 lm point lights of 8 m range, culling took the PBR pass from 4.31 to about 1.2 ms and fog from 0.98 to 0.42 ms at 3200x1809 on an RTX 4090 Laptop GPU. Filling the 256-light budget with 251 extra 400 lm, 6 m lights measures 2.2 to 2.6 ms for PBR, 1.0 to 1.1 ms for fog, and 0.14 ms to build the clusters. Moving lights from the uniform block to the buffer measured no difference beyond this laptop's run-to-run variance, which reaches 15% on the PBR pass; use Nsight GPU Trace to compare changes smaller than that.

Ambient occlusion is GTAO with a visibility bitmask (Therrien et al. 2023), in three compute passes after the depth prepass. The first converts reversed depth into a five-level view-depth chain, using XeGTAO's mip filter so thin foreground edges do not pull coarse texels forward. The second runs at half resolution on mip 1: each pixel marches 1 to 3 screen-space slices (Low, Medium, High) with 3 or 4 steps per side, and each sample marks the 32 cosine-weighted sectors between its front face and a surface 30 cm behind it, out to a 75 cm radius. Rails, posts, and thin walls therefore occlude only what they actually cover instead of darkening everything behind them. It also writes a view-space bent normal, the mean open direction, which the sector bit planes give without a per-sector loop. The third pass denoises and upsamples in one step: every full-resolution pixel averages the 4x4 half-resolution texels around it, which covers the fixed 4x4 noise pattern exactly, weighting each by its distance from the pixel's depth plane. Nothing depends on history, so it needs no TAA. The PBR pass applies the result only to sky and environment light: diffuse uses Jimenez's multi-bounce fit and the bent normal's offset from the surface normal, and specular uses Lagarde's specular occlusion. Direct lights are never occluded. In October 2026, High measured 0.43 ms on average at 3200x1809 on an RTX 4090 Laptop GPU (depth 0.06, occlusion 0.17, denoise 0.21), and 0.4 to 0.9 ms across the Sandbox bookmarks. The first full-resolution version, with four slices of eight steps, cost 2 to 5 ms. Known limits: features thinner than about four pixels, such as the bay pillars seen from afar, keep some of the noise pattern because their neighbors are rejected, and walls at grazing angles show faint streaks. Off, and targets with fewer than five mips, skip the passes and bind a white texture.

Quality tiers are presets over the settings that cost GPU time; `ApplyRenderQuality` sets them and `FindRenderQuality` recognizes a matching preset, so the viewport's Quality combo shows Custom once a single setting is changed. Low is SMAA Low, hard shadows at half resolution (1024 px cascades, 256 px local tiles), no ambient occlusion, and fog at an eighth of the view capped at 256 px. Medium is SMAA Medium, soft shadows at half resolution, GTAO Low, and quarter-resolution fog. High, the default, is SMAA High, full-resolution soft shadows, GTAO High, and quarter-resolution fog capped at 512 px. Half-resolution shadows shrink the atlas with them and keep its normalized layout. The game's pause menu cycles the tiers and saves them, and editor Play uses the viewport's settings. `HertaEditor --visual-test --quality=low|medium|high` measures one tier. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, the nine Sandbox bookmarks averaged 1.26 ms of GPU time on Low, 2.94 on Medium, and 3.37 on High, with 197, 255, and 315 MB of render targets.

Occlusion culling is two-phase and off by default (`FVisualSettings::bOcclusionCulling`, the viewport's Occlusion culling toggle). The camera's frustum-culled instances become candidates with world bounds. An early compute pass lists those that passed last frame, and the instanced depth prepass draws them. A compute pass then builds a depth hierarchy: level 0 is the largest power of two within half the view, each texel holding the farthest reversed-Z depth of the up to 5x5 pixels it covers, and every coarser level is an exact 2x2 reduction. One 16x16 group writes five levels from shared memory, so 3200x1809 takes three dispatches. The late pass tests every candidate's projected box at the level where it spans at most 2x2 texels, records the result for the next frame, lists newly visible instances for a second depth prepass, and lists everything visible for shading. Each list is a range of indirect draw arguments and a copy of the instances, so draw calls stay one per batch section. Because the late phase tests against this frame's depth, a revealed object is never drawn a frame late; a stale history only costs work. `--renderer-test` hides a cube behind a wall, requires the image to match culling off, then moves the wall and requires the cube in that same frame. It is off because nothing it can skip is expensive yet: the depth-equal PBR pass already shades only visible pixels, and Sandbox and scaling meshes are a few hundred triangles. The hierarchy costs 0.08 ms and the two cull passes 0.03 ms at 3200x1809 on an RTX 4090 Laptop GPU, and enabling it made Sandbox bookmark frames about 0.35 ms slower and a grazing view over the 10,000-cube scaling fixture no faster. Turn it on by default when levels carry hidden meshes with heavy vertex work, after measuring them.

Motion vectors are opt-in through `FVisualSettings::bMotionVectors` until temporal AA reads them, and `FMeshRenderer::GetMotionVectors` returns them: an Rg16Float target holding this frame's UV minus the previous frame's. Every mesh instance carries last frame's object-to-clip transform, built from the previous camera and `FMeshRenderView::PreviousModels`, and the instanced depth prepass writes object motion while it lays down depth. Pixels it does not write, the sky, custom-material surfaces, and renderers without instancing, keep a sentinel that a compute pass after shading replaces with camera motion reprojected from depth. Custom-material surfaces therefore report camera motion only, and over prepass geometry they keep that geometry's motion until custom vertex shaders write their own. A changed view extent restarts motion; explicit camera cuts arrive with temporal AA. `FGameSession` supplies previous models, so Play and the game report body and platform motion; the editor viewport treats models as static. The camera pass costs 0.12 ms at 3200x1809, and writing motion during the prepass measured no extra cost. `--renderer-test` checks a moving cube's motion against its projection over a still sky, and that a camera turn moves the cube and the sky above it alike.

## Shader cooking

Compute shaders live in `Engine/Shaders/Compute` and cook their `computeMain` entry point to `<Name>.comp.hshader`. They sample t0..t15 through a clamped s0, point or linear per pipeline, read `StructuredBuffer`s at t16..t23 and uniforms at b0, and write storage images and then `RWStructuredBuffer<uint>` storage buffers at Vulkan bindings 384..391. Storage images declare an explicit `[format(...)]`. A storage buffer can also supply indirect dispatch arguments.

The pinned Vulkan SDK supplies Slang. Setup validates its headers and compiler libraries on Windows and Linux. `ShaderCompiler` is a Developer module; runtime rendering depends only on RHI's cooked reader.

Building `HertaEditor` first builds `HertaShaderWorker` and runs the `HertaShaders` target. It cooks the mesh, shadow, sky, fog, tone-map, SMAA, grid, and debug shaders into `Shaders/*.hshader` beside the executable, including instanced mesh and shadow variants. Builds do not download anything. Shipping strips shader debug information; the runtime renderer consumes cooked shaders without depending on Slang.

Cooked files contain explicit little-endian versioned fields, stage and entry point, SPIR-V, reflected bindings and push-constant size, compiler version, permutation settings, source dependency hashes, and a content checksum. The reader bounds sizes and rejects corrupt or incompatible files. A successful cook atomically replaces the output; failure preserves the previous file.

Release cooks are byte-identical across checkout directories for identical sources and compiler settings. Slang debug information embeds absolute include paths, so Debug and Development artifacts can differ across checkout locations even when their code and dependency hashes match.

Manual invocation:

```text
HertaShaderWorker <source.slang> <vertex|fragment> <entry-point> <output.hshader> [--debug] [--include-root <path> ...]
```

Existing files under `Engine/Shaders` participate in build dependencies. Regenerate project files when adding a shader or include file. The editor also watches material shader sources and literal includes/imports, compiling immutable snapshots asynchronously through the worker. Compatible vertex, instanced vertex, and fragment pipelines publish atomically; failure retains the last valid pipeline. See [Materials](Materials.md) for mounted paths and the exact shader ABI.

## Profiling

Every timed pass also opens a Vulkan debug label of the same name, and `VK_EXT_debug_utils` is enabled whenever the loader offers it, so RenderDoc and Nsight Graphics captures group work by pass. Nsight Graphics GPU Trace reports per-pass hardware limiters such as SM, texture, L2, and DRAM throughput:

```powershell
& "C:\Program Files\NVIDIA Corporation\Nsight Graphics <version>\host\windows-desktop-nomad-x64\ngfx.exe" --activity "GPU Trace Profiler" --exe Binaries\windows\x86_64\Development\HertaEditor.exe --dir . --args --visual-test --start-after-frames 450 --limit-to-frames 1 --architecture Ada --metric-set-name "Throughput Metrics" --multi-pass-metrics --auto-export --output-dir <folder>
```

It needs GPU performance counter access for non-admin users (NVIDIA Control Panel, Developer, Manage GPU Performance Counters). `D3DPERF_EVENTS.xls` holds per-label times and `GPUTRACE_REGIMES.xls` the metrics per range. GPU Trace runs at base clocks with CPU overhead, so idle gaps land in whichever range is open; compare durations with the `--visual-test` averages and use GPU Trace for which unit limits a pass.

## Verification

`HertaTests` covers camera/picking and viewport input ownership, grouped authoring, graph/resource failure cleanup, renderer projection/winding, PBR material serialization and color-space/channel rules, normals/tangents, HDR environment filtering, light/shadow budgets, shader reflection and deterministic compilation, and shader snapshot coalescing with last-valid publication.

`HertaEditor --renderer-test` checks instanced versus single-draw GPU image equivalence, GPU image coverage, multi-section render meshes with per-section textures and uploaded mip chains, near-over-far depth occlusion, depth-tested and overlay debug primitives, point pixel size, recording cancellation, fence retirement, repeated offscreen resize/zero extents, and native resize/minimize/restore requests, then exits. It also locks the exposure calibration: an 18% grey, fully rough card under 100,000 lx of overhead sun at EV100 15 ("sunny 16") must display as neutral middle grey, between 98 and 116 in sRGB (it reads 107, because GT7 keeps the camera's 14.6% exposed grey nearly linear). The native resize sequence also switches panel blur between zero, normal, and maximum radius to exercise backdrop allocation and reuse. Where windows can be placed, which excludes Wayland, it then floats the Content Browser and Details panels, which show renderer thumbnails and previews, across the main window's edges so each gets its own native window and swapchain, resizes them, and resets the layout, requiring three platform windows while floating and one after. Development renderer tests require Vulkan validation instead of silently running without it. Smoke runs store layout and appearance under `TestResults/Smoke`.

`HertaEditor --visual-test --validation` renders the normal Sandbox playground and camera in a maximized window with the F11 full viewport, the most pixels a normal session renders, until 600 presented, asset-ready frames complete, then exits. It uses isolated layout/appearance settings rather than loading or writing personal preferences, and has a five-minute loading/presentation deadline. The log reports viewport size and total render-target bytes. It also reports the average wall time, CPU phases (render recording, swapchain acquire, ToolUI, and present), ToolUI GPU time, and GPU time for each visual pass over the last 599 frames. Single-frame GPU timings swing with clocks, so the averages are the numbers to compare. It then visits each of the level's camera bookmarks in slot order, lets each settle for 60 frames, logs its GPU time averaged over the last 30 with the passes above 0.1 ms, heaviest first, and its draw count, and saves the viewport, overlays included, to `Saved/VisualTest/00-Start.png` and `NN-<Bookmark name>.png`. This exercises the authored material/light/sky/fog/SMAA path; the images are for review, not a screenshot comparison, and do not replace checking appearance in the editor.

`--visual-test --resolution=WIDTHxHEIGHT` renders the viewport at a fixed size, up to 4096 per side, and shows it scaled to the panel, so timings compare across displays. In October 2026 on an RTX 4090 Laptop GPU at the High tier, the starting view measured GTAO at 0.11 ms at 1920x1080 (depth 0.02, occlusion 0.04, denoise 0.05) and 0.80 ms at 3840x2160 (0.12, 0.32, 0.38). SMAA High measured 0.42 ms at 3840x2160 (edges 0.26, weights 0.04, neighborhood 0.11) and 0.15 to 0.35 ms at 1920x1080: a 1080p frame leaves the GPU lightly loaded, and its clocks vary between runs. The nine bookmarks averaged 0.98 ms of GPU time at 1080p and 3.92 ms at 4K.
