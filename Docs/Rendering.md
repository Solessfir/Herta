# Rendering

See the [Milestone 4.5 completion report](Milestone45.md) for verified platforms, playground captures, measured budgets, and remaining limitations.

The editor renders authored levels through a native HDR PBR pipeline beneath the docked panels. The camera uses a 65-degree vertical perspective field of view. Viewport layout and camera input are resolved before rendering, so resizing uses the current frame's aspect ratio. Render-target size limits scale both dimensions together. The depth-tested meter grid uses subdued major lines and distance fading. Saved workspace layouts remain intact.

## Ownership

- `RHI` owns resource descriptors, shared GPU handles, the graphics device contract, and the versioned cooked shader format. Calls belong to one render thread; all resource handles must be released before the owning presentation device.
- `NvrhiVulkan` privately maps those operations to NVRHI. Three independent command contexts retain recorded resources and upload storage until their graphics-queue submission serial completes. Cancelling a recording releases CPU commands without submitting GPU work.
- `RenderGraph` validates declared reads/writes, derives resource hazards, orders passes deterministically, and scopes transient ownership to first and last use. RHI retention extends GPU lifetimes past graph execution. This first graph runs on the graphics queue; asynchronous compute is deferred. `IGraphicsDevice::CreateAliasedTextures` places textures whose lifetimes never overlap in one allocation: each phase's textures sit side by side and the phases overlap. A texture's first use in each recording must overwrite all of it; the device then transitions it from an undefined layout through a native barrier, ending any open render pass first, because NVRHI cannot track an undefined prior state. GTAO's view depth, noisy and denoised occlusion, and the contact shadow mask live only until the mesh pass reads them, and the tone-mapped copy and SMAA's edges and weights only from tone mapping on, so the two groups share one allocation: High-tier render targets at 3200x1809 fell from 405 to 339 MB. Global illumination's buffers and atlases, about 136 MB, are counted separately and are not aliased.
- `Renderer` owns GPU meshes/materials, HDR and display targets, shadows, environment lighting, fog, tone mapping, SMAA, and grid/debug passes. It owns no content: the editor supplies view/projection, model matrices, material-slot overrides, lights, environment settings, and overlays. Null meshes, such as ones still loading, are skipped.
- `FRenderMesh` is the GPU copy of a cooked model: vertex/index buffers, imported material defaults, mip-mapped textures, sections, and bounds. `FRenderMaterial` owns editable parameters and texture handles separately. Instances sharing one GPU mesh and material-slot overrides batch into indexed instanced draws. Recorded frames retain handles, so replacement never waits for the whole GPU.
- Each frame culls world-space mesh bounds against the camera, every shadow view, and the visible selection. Local shadow views also cull against the light's range, because their projections have no far plane. Culled instances for all views are stored back to back in one instance buffer that grows by powers of two. Meshes with per-frame vertex updates, such as soft bodies, are never culled, because they can deform beyond their cooked bounds.
- `EditorCore` owns the viewport camera math. `EditorFramework` owns input routing, the preview transform, and its private im3d context; it copies im3d output into Herta debug primitives before rendering.

The world grid is a two-triangle GPU procedural pass after opaque geometry, with reversed-Z depth testing and no depth writes. `WorldGrid.slang` evaluates anti-aliased 1 m minor and 5 m major lines, fading from 50 m to 200 m around the camera. Only four projected vertices are uploaded per frame; the grid does not enter the CPU debug-line expansion path.

Uploads use NVRHI staging with a 64 MiB per-recording limit, exposed as `MaximumUploadBytesPerRecording`. `FRenderMesh::Create` submits and begins a new recording whenever the next write would exceed it, so a 4096x4096 texture with its mips uploads across several recordings. Textures are uploaded one mip level at a time and cannot be sampled until every level has been written. Frame reuse waits only for that context's submission, rather than waiting for the entire device every frame. Readback is an explicitly blocking diagnostic operation.

Draw uniforms use NVRHI volatile constant buffers, which suballocate each write from the upload ring. Ordinary buffer writes would end the render pass and add a barrier before every draw. Each recording creates a framebuffer once per target pair and a binding set once per pipeline layout and resource combination, then reuses them for every draw.

VSync is enabled by default and can be toggled from the application menu. The change is applied between frames by recreating the main and detached viewport swapchains with FIFO or the best available non-VSync present mode.

The scene uses column-major matrices, a +Z-forward camera, counter-clockwise front faces, infinite-far reversed-Z projection, depth clear `0`, and `GreaterOrEqual` depth testing. NVRHI supplies Vulkan's viewport Y inversion; shaders do not flip Y again.

Meshes carry cooked normals and tangents with explicit handedness. Surface lighting uses metallic-roughness GGX PBR (see the BRDF below), authored lights, and filtered environment lighting. The instanced vertex stream carries object-to-clip and object-to-view matrices (128 bytes per object). Single draws retain the 128-byte push-constant ABI. Unlit new levels and asset thumbnails have a studio preview; authored lighting replaces it.

Color textures use sRGB sampling; numerical maps use Linear. Scene lighting and fog accumulate into RGBA16F HDR targets. Exposure and GT7 tone mapping produce the sRGB display target. ToolUI samples the completed image through an UNORM view so UI composition does not decode it twice.

## Viewport interaction

Use RMB with WASD and QE for fly navigation, Alt+LMB to orbit, MMB to pan, and the wheel to dolly. While flying, the wheel adjusts movement speed and Shift accelerates movement. F focuses the selection. The viewport toolbar exposes translation, rotation, scale, local/world axes, and snapping.

Camera and gizmo drags start only over the viewport image. They keep ownership through the drag and release it on focus loss or cancellation, so other editor widgets cannot drive the camera. Grid, axes, and bounds use level depth; transform handles draw as an overlay. Level owns authored entities; EditorFramework adapts their transforms to the viewport and records grouped authoring transactions for undo/redo.

Click a mesh or editor marker to select its entity; click empty viewport space to deselect. Ctrl/Shift-click toggles additional entities, and dragging from empty space box-selects projected bounds. Selection shows transform handles and a two-pixel outline of the rendered meshes, including alpha cutouts, dimmed where other geometry hides them. The outline rasterizes the selected meshes into a selection depth target with the depth-only shadow pipeline and composites after SMAA, shading only the selection's projected screen bounds. Camera navigation and gizmo clicks preserve selection. Light and environment components have typed editor guides, including selected ranges and emitter shapes. G hides authoring overlays without hiding the optional camera coordinates or entering Play.

Details and gizmos edit world-space location in meters, XYZ Euler rotation in degrees, and positive per-axis scale; levels store parent-local transforms. Compact RGB-marked fields omit axis labels and trailing zeros. Changed properties expose revert arrows. Locking scale preserves all three starting proportions and rejects edits outside the positive supported range. Search filters properties and components. Multi-selection changes are grouped into undoable gestures and saved with the level. With no selection the panel displays a selection prompt.

Translation and scale use small colored plane handles. Scale plane handles change two local axes together while preserving their starting ratio. During dragging, translation displays meters, scale displays multipliers relative to the starting scale, and rotation displays the signed applied angle with a swept sector. Dotted guides replace full-length axis lines; releasing or cancelling hides the feedback.

Q hides the transform gizmo without deselecting; W/E/R select move/rotate/scale and show it again. L switches local/world axes while the viewport owns keyboard focus. These shortcuts do not override RMB flight controls. Escape cancels a transform drag and restores its starting transform. Alt+RMB also dollies. RMB navigation hides the pointer. Changing the flight speed with the mouse wheel or the Camera speed slider shows it, including Shift acceleration, for 1.5 s after the last change. The toolbar's Grid (m) field sets the translation snap interval. Navigation uses ordinary pointer motion, so a continuous drag is bounded by the desktop edge; Play captures the pointer for relative look.

im3d is pinned under `External/im3d` and is private to EditorFramework. The renderer accepts Herta-owned points, lines, and triangles. Pixel-width lines and points expand to triangles without requiring geometry shaders or native wide-line support.

## Visual authoring

[Materials](Materials.md) describes editable PBR assets, mesh slots, and project Slang iteration. Directional, Sky, Point, Spot, and Rect lights are independently optional level components, available through placement and Add Component. Details exposes linear color or temperature, physical intensity, range, shadow biases, spot cones, and rectangle dimensions. Directional range sets shadow distance, 60 m by default, and the last cascade fades out over its final 15%.

The renderer admits at most 256 enabled lights in stable entity order. Shadows use at most 16 views in two reversed-Z atlases. The first shadow-casting Directional light owns four 4096x4096 cascades in an 8192x8192 16-bit atlas (128 MB); orthographic depth over a cascade's few hundred metres keeps millimetre precision in 16 bits, at half the memory and sampling bandwidth of 32. Further directional lights cast no shadows. Point (six faces), Spot, and Rect (one each) share a 4096x1024 32-bit atlas (16 MB), because their perspective depth needs the precision. Each local light's tiles are sized by how large its reach looks on screen, from 128 px for distant lights to 1024 px when the camera is inside its range; when the total exceeds the atlas, the largest tiles halve, later lights first, and tiles pack largest first into power-of-two cells, which always fits once the area does. Distant lights therefore cost a sixteenth of the draw and nearby ones get four times the texels of the fixed 512 px tiles used before October 2026. Each cascade is a sphere around its slice of the view, snapped to whole texels so its shadows do not crawl as the camera moves, and the last tenth of each cascade blends into the next so their resolution change does not show as a line. Cascades cover only the depth the camera sees: a compute pass reduces the depth buffer to its nearest and farthest surfaces (0.04 ms at 3200x1809), and the renderer reads that back two frames later without stalling, widens it by a quarter, and rounds it to quarter octaves so the cascades change size rarely. A view that ends 15 m away therefore puts the texels meant for the whole 60 m shadow distance into those 15 m. The last cascade also serves anything it covers beyond its split, which bridges the readback delay when the view suddenly reaches farther. With the 2048 px cascades used before October 2026, each shadow texel covered 5 to 9 screen pixels at the start of each cascade at 3200x1809, which showed as stepped edges; the split scheme was already close to a logarithmic one with lambda 0.95, so only resolution could fix it. Redrawing every view at 4096 px costs about 0.45 ms, against 0.11 to 0.2 ms at 2048, and happens only on frames where the sun's cascades move; refreshing the farthest cascade only every other frame was measured and rejected, because with the depth-fitted range it is not the expensive one: forcing every view to redraw, the shadow pass took 0.50 to 0.64 ms with or without it. Admission is whole-light, so insufficient space disables that light's shadows rather than rendering incomplete cube faces. Cascade normal offset scales with each cascade's world texel size. Viewport settings exposes Off, Hard, and Soft shadows and the budgets; both use bilinear-weighted PCF over 2x2 and 4x4 texels, read with one and four gathers. Soft sun shadows are percentage-closer soft shadows: five gathers find the occluders around a lookup, and their average distance times the light's source angle (the sun's disc is 0.53 degrees, authored per directional light) sizes the filter, so shadows stay crisp where an object meets the ground and soften with distance. Pixels with no occluder, or occluders all around a filter that fits the search, stop after the search; the rest take 16 bilinear taps on a fixed Vogel spiral, because a per-pixel rotation would leave grain that only temporal accumulation removes. The filter is clamped at four texels, where those taps still overlap smoothly, and each tap compares against the receiver's plane extended from its normal in light space, which keeps wide footprints on sloped or grazing surfaces from shadowing themselves. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU this cost about 0.06 ms of PBR shading. Local lights keep the fixed 4x4 filter. Viewport settings also offer penumbra saturation, a stylization that is off at its default of 1: each light's diffuse contribution is weighted by 4V(1 - V), which peaks halfway through its penumbra, and that part of the diffuse colour is saturated around its own luminance, up to 4x, so shadow edges pick up the painterly coloured terminator. It is not physically based, adds energy to the dominant channel, and is clamped so no channel goes negative. Contact shadows add what the cascades are too coarse to resolve where objects meet surfaces: Bend Studio's screen-space shadows ([vendored](../External/BendScreenSpaceShadows/UPSTREAM.md), Apache 2.0) march each wave of 64 pixels along one shared ray toward the cascaded sun through the depth prepass, 60 samples deep, in one to six dispatches depending on where the sun projects. Waves that are all sky stop before marching. The dispatches write disjoint pixels, so they run without storage barriers between them (`FComputeDispatch::bOverlapsPrevious`), which measured 0.204 against 0.211 ms. The result multiplies only that sun's visibility. They cost about 0.23 ms at 3200x1809, so only the High tier enables them; Viewport settings toggles them. Surfaces drawn by custom material shaders, which skip the depth prepass, neither cast nor receive them. The depth prepass draws visible opaque and cutout geometry with the PBR vertex shaders and the masked depth shader, then PBR shading tests for equal depth without writing it, so each pixel runs the lighting shader once; without it, hidden surfaces drawn first measured about six shaded samples per pixel. Custom material shaders may move vertices, so they skip the prepass and write their own depth. Small or alpha-tested geometry such as foliage can use the same path: a cutout depth pass discards twice and small pieces occlude little, so engines often keep only large occluders in the prepass (Unreal's `r.EarlyZPass` 1). Add that filter, by cutout material or screen size, once dense vegetation exists to measure it. Surfaces skip shadow filtering for lights that contribute nothing, and Rect lighting skips pixels behind the emitter or out of range. Rect surface lighting uses linearly transformed cosines (Heitz et al. 2016) with the published GGX fit in [External/ltc](../External/ltc/UPSTREAM.md): two 64x64 tables turn diffuse and specular into closed-form clamped-cosine integrals over the emitter quad, within a few percent of brute-force GGX, so glossy surfaces show a solid rectangular highlight. Rect range is measured from the emitter's surface, and Rect shadows are a single center projection, not soft area shadows. There is no light baking or dynamic GI.

Sky Light filters a cooked HDR environment or the procedural atmosphere into diffuse irradiance and roughness-dependent GGX specular mips. Filtering runs on background tasks and keeps the previous environment while updating. Visibility and ambient strength are independent. Sky Atmosphere links a directional sun and ray-marches single-scattering Rayleigh, Mie, and ozone from sea level, using the authored scattering scales, anisotropy, planet radius, and atmosphere height. Multiple scattering uses Hillaire's 2020 transfer table (Psi_ms): a 32x32 RGBA32F table over sun cosine and altitude, integrating second-order isotropic scattering over 64 directions with Earth's 0.3 ground albedo and amplifying it by 1 / (1 - f_ms). The CPU builds it only when the scattering scales, planet radius, or atmosphere height change; moving the sun reuses it. With an atmosphere, the directional sun is authored above the air (about 128,000 lx for the real sun). Surfaces and fog receive it multiplied by the transmittance along its direction, so sunsets redden, and once the sun sets direct light stops and the sky falls dark. The visible sun disc has the sun's real luminance, its illuminance over a 0.27 degree radius (about 600 million cd/m2), and clips at the half-float scene-color maximum. Image-based lighting leaves the disc out because the directional light already provides it. Covered interiors still receive unoccluded sky light, because there is no sky occlusion or global illumination, so realistic indoor lamps only read once the sky is dark. Below the horizon, each direction shows the sky's horizon colour for its azimuth, darkening towards the nadir, so an open level reads as distant haze instead of a flat ground plane without repeating the sky's gradient or sunrise glow upside down. Environment filtering bakes the same model into a 128x64 table once per change, then filters it like an authored environment map. Clouds, aerial perspective, and sky occlusion are not implemented. Bloom is not implemented either; when it is, it should use the same dual-filter Kawase downsample/upsample pyramid as the editor glass blur, running on HDR scene color before tone mapping.

Height Fog integrates density, albedo, and anisotropy along view rays to opaque depth. Density is constant below the fog entity's height and falls off exponentially above it, so a void beneath the level is not filled with opaque fog. Ambient in-scattering weights the specular environment, at a mip blurred to their spacing, by the phase function over 64 spherical Fibonacci directions; it varies slowly with the view, so each 8x8 group of fog texels sums one direction per thread for its central ray in shared memory and adds no measurable time. Halving the zenith and nadir irradiance, as before, weighted the sky by |cos| and ignored anisotropy: against the path tracer it lowered the error over the east terrace from 2.4% to 1.3% and the overview from 2.2% to 1.6%. The sky is not occluded: at a fixed exposure fogged sky matches the path tracer within 0.5% on every Sandbox bookmark, and tracing each group's 64 directions against the scene, with blocked ones taking the shaded surface they meet, moved whole-image error by -0.2% to +0.24% while costing up to 0.4 ms in the lighting bays. Lights scatter through a Henyey-Greenstein phase function whose positive anisotropy brightens fog looking towards them; until October 2026 the angle was reversed, so fog glowed looking away from the sun. Volumetric mode adds supported lights and shadow visibility with 16/32/64 steps. Fog always uses the Hard 2x2 shadow filter, since the dither and upsample already soften it and Soft filtering would quadruple the loads at every step. The fog target is quarter resolution, capped at 512 pixels per dimension. Each fog texel offsets its samples along the ray by interleaved gradient noise, so shadow shafts dither instead of stepping into slabs. The ray march is a compute pass that also stores the scene depth at each texel centre; a second pass averages the dither with a depth-aware 3x3 Gaussian at fog resolution, and tone mapping composites fog with a bilinear upsample weighted by depth similarity, reading the four texels' depths with one gather, so there is no separate full-resolution composite target. Doing the Gaussian per screen pixel kept tone mapping at 22 texture fetches per pixel with the texture pipe 94% busy; now it takes 9. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, tone mapping dropped from 0.38 to 0.13 ms and fog with its denoise from 0.24 to 0.18 ms. Exposure metering applies fog to its own taps. Disabling volumetric mode keeps height fog at eight integration steps. There is no temporal history, so cuts and resize need no history reset; very long rays at Low quality can still show fine grain.

The pass order is shadow atlas, light clusters, HDR sky, a depth prepass (split around the depth hierarchy with occlusion culling), ambient occlusion, PBR geometry, optional motion vectors, quarter-resolution fog and its denoise, automatic exposure, the tone-map LUT, fog composite with exposure/tone mapping, SMAA 1x, then grid/debug overlays and ToolUI. Work whose inputs did not change keeps last frame's result: each shadow tile redraws only when its projection, a caster's transform, mesh, or masked material inputs, or a deforming mesh it sees changes, and the light upload, light clusters, sky view table, and tone-map LUT recompute only when the values they read change. A still camera over the Sandbox draws 23 to 80 times per frame instead of 165 to 237; a moving camera redraws the cascades and keeps local light tiles. A recording that fails to submit resets every key. Exposure is photographic EV100: the tone mapper scales scene luminance by 1 / (1.2 * 2^EV100), the saturation-based convention from Lagarde and de Rousiers. The editor derives EV100 from the viewport's physical camera aperture, shutter, and ISO, or meters it automatically. Automatic exposure stays on the GPU in one dispatch of a single 256-thread group: it samples the HDR scene into a 32x32 grid of centre-weighted log luminance, builds a 64-bin histogram with shared-memory atomics, and averages its 10th to 90th percentile so a few highlights or deep shadows cannot swing it, converts that to reflected-light EV100 (log2(L) + 3) with a one-stop brighter bias, as Unreal does by default, so sunlit scenes with bright sky meter near "sunny 16", clamps it to EV100 1 to 18 so night scenes stop at a night-street exposure, and eases towards it with rates of 3/s brightening and 1.5/s darkening. Tone mapping reads the resulting one-pixel exposure, so nothing is read back to the CPU. The tone mapper is a port of Polyphony Digital's GT7 operator ([reference](../External/gt7/UPSTREAM.md)): exposed 1.0 becomes its 250 cd/m2 SDR paper white, the GT curve maps each Rec.2020 channel, and the result blends 60% towards a version that keeps the original ICtCp hue and fades chroma to white near the peak. Midtones stay nearly linear and saturated highlights keep their hue instead of skewing. Whenever the display's paper white or peak changes, the operator is baked into a 64x64x64 RGBA16F LUT over exposed log2 values from 2^-12 to 2^8, unwrapped into a 4096x64 target; the full-screen pass reads it with two filtered taps. 32 steps put saturated highlights more than 20 sRGB levels off, because the hue-preserving fade bends sharply; 64 keeps the 99.9th percentile within 3 levels. SDR output divides by paper white; HDR10 output reuses the same curve with the display peak and writes a half-float display target relative to paper white, which ToolUI encodes; see [HdrOutput.md](HdrOutput.md). Automatic exposure costs about 0.03 ms, down from 0.07 ms as three full-screen passes. Viewport settings provides the camera, the quality tier, SMAA Off/Low/Medium/High/Ultra, shadow quality, ambient occlusion, and occlusion culling; the Performance panel reports GPU pass timings and render-target memory. Defaults are the "sunny 16" EV100 15 (f/16, 1/125 s, ISO 100), SMAA High, and Soft PCF shadows. SMAA uses the [unmodified reference implementation and lookup data](../External/SmaaUpstream.md). It does not resolve temporal subpixel shimmer, and requires no motion vectors or history. Edge detection and blending weights run as compute, following Jimenez's Filmic SMAA (SIGGRAPH 2016): the edge pass writes edges for every pixel and appends each edge pixel to a list, reserving slots with one atomic per wave and counting 64-pixel groups as it goes, so the weight pass is an indirect dispatch over the list with no setup pass. The list holds one uint per pixel, 23 MB at 3200x1809. Neighborhood blending stays a full-screen pass because it writes the sRGB display target. The full-screen edge and weight passes remain as the reference; `--renderer-test` requires the compute path to match them within one 8-bit level. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, the weight pass dropped from 0.14 to 0.03 ms and edges stayed at 0.17 ms, taking SMAA High from 0.40 to 0.28 ms. Edge detection reads nine colors per pixel without shared memory; caching them per group is the next step if it matters.

The BRDF follows the real-time subset of OpenPBR. Specular is GGX with height-correlated Smith visibility and Schlick Fresnel; metals add F82-tint (Hoffman 2019), so the material's edge color scales reflectance near 82 degrees. Single-scattering GGX loses energy as roughness grows, 69% for a fully rough lobe seen head on, and Turquin's (2019) scale 1 + F0 (1 / E - 1) restores it. Diffuse is EON (Portsmouth, Kutz, and Hill 2024), the energy-preserving Oren-Nayar model OpenPBR adopted; diffuse roughness 0 is exactly Lambert and skips it. Like Unreal Engine 5.8's EON, it uses cheap fits: Fujii's scale as a line (within 0.014), the view albedo with G / pi fitted by least squares as 0.2624 (1 - mu) (within 0.026), and multiple scattering as rho^2 (1 - E) towards the view only, which still reflects all light from a white surface at every angle. The authored color is inverted into the single-scattering albedo whose cosine-weighted average reflectance equals it, solving the quadratic exactly, so raising diffuse roughness reshapes shading without darkening or saturating the color. Diffuse receives what the dielectric specular layer does not reflect toward the view, OpenPBR's albedo scaling, so the two layers sum to at most one. A 32x32 half-float table, integrated once per process with the shader's own GGX and Smith terms, gives the specular lobe's directional albedo by view angle and roughness: the split-sum terms A and B and the F82 integral C. The environment, multiple-scattering compensation, and albedo scaling all read it, replacing Karis's analytic fit. Environment diffuse uses EON's directional albedo in place of its lobe; rect lights lose only EON's s / t shaping and leave out the edge tint, because their LTCs integrate cosine and GGX lobes. `--renderer-test` runs a white furnace: Lambert, rough EON, and a rough white metal must read the same under 240 directional lights spread over the sphere and under a uniform environment. They read 117 of 255 each, and without compensation the metal reads 59. A grey round compares 50% grey Lambert with rough EON: 80 against 78, where the inversion matches average reflectance and the head-on view sits slightly below it; without the inversion it would read about 75.

The lighting pass is register-limited: Nsight GPU Trace shows warp launches waiting on registers most of the time. With the material terms inside the light loop the driver recomputed them for every light, and the pass ran 25% more instructions than the Lambert version. Lights therefore add material-independent sums, a diffuse irradiance, EON's multiple-scattering weight, and the GGX lobe with its two Fresnel weights, and the material applies once afterwards. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU this BRDF executed 66.8 million instructions in the PBR pass at the starting view against 67.7 million for the earlier Lambert, Schlick, and analytic-split-sum shader, and whole-frame GPU time did not change beyond run-to-run variance.

Lights are culled into clusters: 64-pixel screen tiles by 24 exponential depth slices from 0.1 to 500 m, the last slice reaching to infinity. Light data lives in a storage buffer that shaders read as a `StructuredBuffer` through `VisualLights.slangh`, so only the camera, sky, fog, shadow, and material fields remain in the per-draw uniform block, and shaders that need just the sun read `Visual.SunDirection` and `Visual.SunRadiance`. A compute pass gives each cluster eight uints, one bit per light, set for the lights whose bounding sphere touches the cluster's view-space box. Directional lights are always set, sky lights never; spot and rect lights use their range sphere, rect lights grown by half their diagonal because their range starts at the emitter's surface. The PBR and volumetric fog shaders look up their cluster from the pixel and view depth and loop over its set bits only, with the first 32 lights in their own loop. Renderers without the cluster shader, such as thumbnails, bind one all-set mask. With the Sandbox's then 32-light budget filled by 27 extra unshadowed 800 lm point lights of 8 m range, culling took the PBR pass from 4.31 to about 1.2 ms and fog from 0.98 to 0.42 ms at 3200x1809 on an RTX 4090 Laptop GPU. Filling the 256-light budget with 251 extra 400 lm, 6 m lights measures 2.2 to 2.6 ms for PBR, 1.0 to 1.1 ms for fog, and 0.14 ms to build the clusters. Moving lights from the uniform block to the buffer measured no difference beyond this laptop's run-to-run variance, which reaches 15% on the PBR pass; use Nsight GPU Trace to compare changes smaller than that.

Ambient occlusion is GTAO with a visibility bitmask (Therrien et al. 2023), in three compute passes after the depth prepass. The first converts reversed depth into a five-level view-depth chain, using XeGTAO's mip filter so thin foreground edges do not pull coarse texels forward. The second runs at half resolution on mip 1: each pixel marches 1 to 3 screen-space slices (Low, Medium, High) with 3 or 4 steps per side, and each sample marks the 32 cosine-weighted sectors between its front face and a surface 30 cm behind it, out to a 75 cm radius. Rails, posts, and thin walls therefore occlude only what they actually cover instead of darkening everything behind them. It also writes a view-space bent normal, the mean open direction, which the sector bit planes give without a per-sector loop. The third pass denoises and upsamples in one step: every full-resolution pixel averages the 4x4 half-resolution texels around it, which covers the fixed 4x4 noise pattern exactly, weighting each by its distance from the pixel's depth plane. Nothing depends on history, so it needs no TAA. The PBR pass applies the result only to sky and environment light: diffuse uses Jimenez's multi-bounce fit and the bent normal's offset from the surface normal, and specular uses Lagarde's specular occlusion. Direct lights are never occluded. In October 2026, High measured 0.43 ms on average at 3200x1809 on an RTX 4090 Laptop GPU (depth 0.06, occlusion 0.17, denoise 0.21), and 0.4 to 0.9 ms across the Sandbox bookmarks. The first full-resolution version, with four slices of eight steps, cost 2 to 5 ms. Known limits: features thinner than about four pixels, such as the bay pillars seen from afar, keep some of the noise pattern because their neighbors are rejected, and walls at grazing angles show faint streaks. Off, and targets with fewer than five mips, skip the passes and bind a white texture.

Quality tiers are presets over the settings that cost GPU time; `ApplyRenderQuality` sets them and `FindRenderQuality` recognizes a matching preset, so the viewport's Quality combo shows Custom once a single setting is changed. Low is SMAA Low, hard shadows at half resolution (1024 px cascades, 256 px local tiles), no ambient occlusion, and fog at an eighth of the view capped at 256 px. Medium is SMAA Medium, soft shadows at half resolution, GTAO Low, and quarter-resolution fog. High, the default, is SMAA High, full-resolution soft shadows, GTAO High, and quarter-resolution fog capped at 512 px. Half-resolution shadows shrink the atlas with them and keep its normalized layout. The game's pause menu cycles the tiers and saves them, and editor Play uses the viewport's settings. `HertaEditor --visual-test --quality=low|medium|high` measures one tier. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, the nine Sandbox bookmarks averaged 1.26 ms of GPU time on Low, 2.94 on Medium, and 3.37 on High, with 197, 255, and 315 MB of render targets.

Occlusion culling is two-phase and off by default (`FVisualSettings::bOcclusionCulling`, the viewport's Occlusion culling toggle). The camera's frustum-culled instances become candidates with world bounds. An early compute pass lists those that passed last frame, and the instanced depth prepass draws them. A compute pass then builds a depth hierarchy: level 0 is the largest power of two within half the view, each texel holding the farthest reversed-Z depth of the up to 5x5 pixels it covers, and every coarser level is an exact 2x2 reduction. One 16x16 group writes five levels from shared memory, so 3200x1809 takes three dispatches. The late pass tests every candidate's projected box at the level where it spans at most 2x2 texels, records the result for the next frame, lists newly visible instances for a second depth prepass, and lists everything visible for shading. Each list is a range of indirect draw arguments and a copy of the instances, so draw calls stay one per batch section. Because the late phase tests against this frame's depth, a revealed object is never drawn a frame late; a stale history only costs work. `--renderer-test` hides a cube behind a wall, requires the image to match culling off, then moves the wall and requires the cube in that same frame. It is off because nothing it can skip is expensive yet: the depth-equal PBR pass already shades only visible pixels, and Sandbox and scaling meshes are a few hundred triangles. The hierarchy costs 0.08 ms and the two cull passes 0.03 ms at 3200x1809 on an RTX 4090 Laptop GPU, and enabling it made Sandbox bookmark frames about 0.35 ms slower and a grazing view over the 10,000-cube scaling fixture no faster. Turn it on by default when levels carry hidden meshes with heavy vertex work, after measuring them.

Motion vectors are opt-in through `FVisualSettings::bMotionVectors` until temporal AA reads them, and `FMeshRenderer::GetMotionVectors` returns them: an Rg16Float target holding this frame's UV minus the previous frame's. While they are on, each mesh instance gets last frame's object-to-clip transform, built from the previous camera and `FMeshRenderView::PreviousModels`, in a second 64-byte instance stream that only the instanced velocity prepass binds, so frames without motion vectors upload 128-byte instances. That prepass writes object motion while it lays down depth. Occlusion culling waits while motion vectors are on, because its culled lists do not carry that stream; both are off by default. Pixels it does not write, the sky, custom-material surfaces, and renderers without instancing, keep a sentinel that a compute pass after shading replaces with camera motion reprojected from depth. Custom-material surfaces therefore report camera motion only, and over prepass geometry they keep that geometry's motion until custom vertex shaders write their own. A changed view extent restarts motion; explicit camera cuts arrive with temporal AA. `FGameSession` supplies previous models, so Play and the game report body and platform motion; the editor viewport treats models as static. The camera pass costs 0.12 ms at 3200x1809, and writing motion during the prepass measured no extra cost. `--renderer-test` checks a moving cube's motion against its projection over a still sky, and that a camera turn moves the cube and the sky above it alike.

## Ray tracing

Ray tracing is capability-driven. When the device offers ray queries, acceleration structures, buffer device addresses, and the descriptor indexing that bindless tables need, the device enables them, and `IGraphicsDevice::SupportsRayQueries` reports it; everything below is absent otherwise and raster rendering is unchanged. NVRHI gives its upload buffers shader-binding-table usage whenever acceleration structures exist, which Vulkan only accepts with `VK_KHR_ray_tracing_pipeline`, so that extension is enabled too, though nothing uses ray tracing pipelines yet. Mesh vertex and index buffers are created with `bRayTracing`, so acceleration structures build from them and ray queries read them in place. A bottom level holds one geometry per mesh section, opaque, so ray queries report the section as the geometry index; a mesh that starts deforming gets a refitting bottom level, and static meshes keep the faster trace. Top levels are built from render extraction; instances with cutout materials are forced non-opaque so their triangles reach the shader's alpha test. A resource table is one descriptor set of unbounded `Texture2D` and `ByteAddressBuffer` arrays at bindings 0 and 1 of set 1, indexed by slots the caller assigns; compute pipelines opt in with `bRayQuery` (the scene at t24) and `bResourceTable`. Slots are rewritten only after every recording that read them has completed. The Sandbox's six meshes take 419 KiB of bottom levels and its 204 instances a 77 KiB top level, so compaction, which would save at most about half of that, is deferred until levels carry enough geometry for it to matter.

The reference path tracer (`FVisualSettings::bPathTracing`, the viewport's Path tracing toggle) replaces raster shading with `Compute/PathTrace.slang`, one sample per pixel per frame, accumulated in an RGBA32F target until the camera, any instance's mesh, transform, or material, the lights, the sky, or the environment changes, and stopped at 4096 samples, when the converged image stays on screen without further work; the viewport shows the count. Exposure, tone mapping, and the editor overlays run as usual; shadow maps, light clusters, GTAO, contact shadows, raster fog, and SMAA do not, because the tracer resolves visibility and fog itself and jitters every sample within its pixel. Fog follows the raster model, so comparisons measure lighting rather than a different fog: it scatters only along camera rays and only within its maximum distance, with the same height density, albedo, and anisotropy. Delta tracking against the larger of the segment's end densities, which bound a density that varies only with height, picks where a camera ray scatters; the scattering point samples lights through the phase function, weighted against the phase-sampled continuation by the same multiple importance sampling as surfaces, and the path goes on to the scene and sky, so fog sees occluded sky and bounce light that raster fog approximates with the unoccluded environment. It shares `Brdf.slangh` with `TexturedMesh.slang`, so a path vertex evaluates exactly the EON diffuse, compensated GGX, and F82-tint reflectance raster shading gives one light, and uses the same light units, attenuation, spot cones, Rect light radiance and one-sided emission, and environment intensity. Hits read vertices and material records through the resource table; textures choose their mip from ray cones (Akenine-Moller et al. 2021), and material maps repeat. Each vertex samples every directional light within its source angle, and one local light chosen in proportion to its unshadowed contribution, with shadow rays that alpha-test cutouts in the candidate loop; BRDF sampling picks the GGX visible-normal lobe or a cosine lobe by their reflectances, and power-heuristic multiple importance sampling weights directional light discs and Rect lights between the two. The environment is reached only by BRDF sampling, which is unbiased but noisy for small bright HDR features; environment importance sampling is the next improvement when an HDR sky needs it. Paths end after eight bounces, with Russian roulette from the third, and emissive surfaces light the scene only when paths hit them. Material ambient occlusion maps are ignored, as the tracer computes occlusion itself. `--renderer-test` requires the tracer to pass the environment furnace (117.6 against raster's 117.0 on an 8-bit 18% grey scale) and to match raster shading under one sun to within three levels on Lambert, rough EON, and rough metal faces that see no other surface; they agree exactly. At 3200x1809 on an RTX 4090 Laptop GPU a sample costs 3.5 to 8.6 ms across the Sandbox bookmarks, so 1024 samples take 4 to 9 seconds; `--visual-test --path-tracing` saves every bookmark at 1024 samples to `Saved/VisualTest/PathTraced`.

Global illumination (`FVisualSettings::bGlobalIllumination`, on in the High tier and the editor's default) is a ray-traced irradiance field after DDGI (Majercik et al. 2019) and its production scaling (Majercik et al. 2021), written from the papers; the RTXGI SDK's license allows no reuse of its code. Probes sit on four clipmap levels of 32x16x32 that follow the camera, spaced 1, 2, 4, and 8 m, so the field reaches about 128 m around it; each level's grid wraps around as the camera crosses cells, so a probe keeps its slot and history while it stays inside, and slots that wrap to a new cell start over. Only probes that something reads trace: the gather marks the eight probes each 2x2 block reads, and those trace every frame; probes only rays read, near the hits of other probes' rays and of reflections, trace every fourth frame while they stay in use. Each traced probe casts 128 rays, shades their hits with emission, sampled direct light, and the field's own irradiance from last frame, so every update adds a bounce, and blends them into a 6x6 octahedral irradiance tile and a 14x14 tile of distance moments, each with a mirrored border. Pixels interpolate the eight probes around them at half resolution, from the prepass's shading normal (with global illumination the depth prepass also writes each pixel's normal-mapped shading normal and roughness into an RGBA8 target, octahedral at 12 bits per axis, through the RHI's second color target when motion vectors take the first), weighted by trilinear position, a wrapped cosine towards each probe, and Chebyshev visibility from the moments, so probes behind walls drop out instead of leaking; the mesh pass blends those gathers on each pixel's surface plane and keeps GTAO for occlusion below the probe spacing. Rays that hit back faces count as five times nearer in the moments, so probes inside geometry read as occluded, and the first 32 rays, the same directions in every probe, drive relocation: a probe that sees mostly back faces moves through the nearest one, and one too close to a surface moves away from it, within 0.45 of the spacing, over its first eight updates only. Probes still inside are left out of shading. Nothing in the field is random from frame to frame: each probe turns its remaining 96 rays by a rotation of its own, fixed by its world cell, and shades their hits with fixed seeds. Rotating every probe's rays each frame, as DDGI does, kept Sponza flickering: a probe in a dark arcade catches a sunlit patch a hundred times brighter with a different number of rays every frame, and keeping 97% of the old value still moved the image by several 8-bit levels. Relocating on every update flickered too, as probes moved back and forth between pushing off a surface and returning to their corner. Each probe averages its first updates evenly and then keeps 97% per update, or 70% where the light changes by more than a third, so newly seen places light up within a few frames and lighting changes settle smoothly. Smooth surfaces up to roughness 0.3 reflect the scene through one mirror ray per block, shaded like the probes' rays with a seed tied to the hit's position, and the mesh pass fades to the environment's filtered reflection by 0.3; rougher reflections stay on the environment, darkened by the gathered sky visibility, until probes keep radiance as well as irradiance. Irradiance is stored at 1/16 scale in half floats, because sunlit irradiance passes their range. The field takes about 136 MB: 32 MB of irradiance and 64 MB of distance tiles, 16 MB of ray results for the 8,192 probes a frame may trace, and the half-resolution gathers. `--renderer-test` requires the open faces in the environment furnace to match raster environment lighting, which they now do exactly (117 against 117 on the 8-bit grey scale; the cascades it replaced read 120), and a still, sunlit view to change by at most one level between frames. NVRHI only revisits resource states when a dispatch's bindings change, so repeated dispatches with identical bindings got no UAV barrier between them; the device places those barriers itself unless `bOverlapsPrevious` asks otherwise. In October 2026 at 3200x1809 on an RTX 4090 Laptop GPU, Sponza traces about 2,000 to 3,000 probes a frame: rays take 0.7 to 0.8 ms, blending 0.1 to 0.2, the gather 0.3 to 0.45, and reflections 0.3 to 0.9, so the starting view runs at 127 fps (7.9 ms) against 67 fps (14.9 ms) with the Split Radiance Cascades it replaced, whose one ray per 2x2 block cost 2.5 to 3.9 ms on its own and grew with resolution. `--visual-test --shimmer` measures what that buys: with the cascades and their stochastic reflections, 2% to 8% of the pixels of Sponza's still bookmarks changed by more than one 8-bit level each frame, and with the field 0% to 0.6%; on the Sandbox bookmarks 0.01% to 0.12%, while their GPU time fell from 5 to 8.5 ms to 2.8 to 4.1 ms. Against the path tracer at 1024 samples the field's mean absolute luminance error is 1.8% to 4.2% on the Sandbox bookmarks, near the cascades' 1.6% to 3.6% and well below 3.0% to 10.1% without global illumination, except the textures bay, whose glossy obsidian floor of roughness 0.4 now reflects the filtered sky instead of the scene and measures 9.3%. The cascades are in the repository history: Split Radiance Cascades (Freeman and Sannikov 2026) with sparse hashed probes fed by one ray per 2x2 block, a world-space hit cache for off-screen bounces, and reprojected stochastic GGX reflections.

## Shader cooking

Compute shaders live in `Engine/Shaders/Compute` and cook their `computeMain` entry point to `<Name>.comp.hshader`. They sample t0..t15 through a clamped s0, point or linear per pipeline, read `StructuredBuffer`s at t16..t23 and uniforms at b0, and write storage images and then `RWStructuredBuffer<uint>` storage buffers at Vulkan bindings 384..391. Storage images declare an explicit `[format(...)]`. A storage buffer can also supply indirect dispatch arguments.

The pinned Vulkan SDK supplies Slang. Setup validates its headers and compiler libraries on Windows and Linux. `ShaderCompiler` is a Developer module; runtime rendering depends only on RHI's cooked reader.

Building `HertaEditor` first builds `HertaShaderWorker` and runs the `HertaShaders` target. It cooks the mesh, shadow, sky, fog, tone-map, SMAA, grid, and debug shaders into `Shaders/*.hshader` beside the executable, including instanced mesh and shadow variants. Builds do not download anything. Shipping strips shader debug information; the runtime renderer consumes cooked shaders without depending on Slang.

Cooked files contain explicit little-endian versioned fields, stage and entry point, SPIR-V, reflected bindings and push-constant size, compiler version, permutation settings, source dependency hashes, and a content checksum. The reader bounds sizes and rejects corrupt or incompatible files. A successful cook atomically replaces the output; failure preserves the previous file.

Release cooks are byte-identical across checkout directories for identical sources and compiler settings. Slang debug information embeds absolute include paths, so Debug and Development artifacts can differ across checkout locations even when their code and dependency hashes match.

Manual invocation:

```text
HertaShaderWorker <source.slang> <vertex|fragment> <entry-point> <output.hshader> [--debug] [--include-root <path> ...]
```

Existing files under `Engine/Shaders` participate in build dependencies. Regenerate project files when adding a shader or include file. The editor also watches material shader sources and literal includes/imports, compiling immutable snapshots asynchronously through the worker. Compatible vertex, instanced vertex, and fragment pipelines publish atomically; failure retains the last valid pipeline. See [Materials](Materials.md) for mounted paths and the exact shader ABI.

## Profiling

Every timed pass also opens a Vulkan debug label of the same name, and `VK_EXT_debug_utils` is enabled whenever the loader offers it, so RenderDoc and Nsight Graphics captures group work by pass. Nsight Graphics GPU Trace reports per-pass hardware limiters such as SM, texture, L2, and DRAM throughput:

```powershell
& "C:\Program Files\NVIDIA Corporation\Nsight Graphics <version>\host\windows-desktop-nomad-x64\ngfx.exe" --activity "GPU Trace Profiler" --exe Binaries\windows\x86_64\Development\HertaEditor.exe --dir . --args --visual-test --start-after-frames 450 --limit-to-frames 1 --architecture Ada --metric-set-name "Throughput Metrics" --multi-pass-metrics --auto-export --output-dir <folder>
```

It needs GPU performance counter access for non-admin users (NVIDIA Control Panel, Developer, Manage GPU Performance Counters). `D3DPERF_EVENTS.xls` holds per-label times and `GPUTRACE_REGIMES.xls` the metrics per range. GPU Trace runs at base clocks with CPU overhead, so idle gaps land in whichever range is open; compare durations with the `--visual-test` averages and use GPU Trace for which unit limits a pass.

### Frame audit

A 2026-10-28 GPU Trace of the High tier at 3200x1809 on an RTX 4090 Laptop GPU averaged 37% SM throughput over the frame, with every pass serialized on the graphics queue. The fixes that followed:

- Fullscreen passes no longer clear targets they overwrite completely (`FIndexedDraw::bCoversColorTarget`), and the sky replaces the scene color clear.
- Shadow tiles, light clusters, the light upload, and the sky view and tone-map tables are cached by their inputs, as described above. A tile is cleared to the far plane by a quad with an always-pass depth test (`FGraphicsPipelineDescriptor::bDepthOverwrite`), because Vulkan clears cannot address part of an image outside a render pass.
- Automatic exposure is one dispatch instead of three full-screen passes that mostly drained the pipe.
- Fog composite fetches dropped from 22 to 9 per pixel, as described above.

Measured and left as they are:

- GTAO denoise costs about 0.1 ms in alternating A/B runs, close to GTAO itself; single per-pass readings up to 0.64 ms were timer noise. Writing 2x2 pixels per thread to share their taps measured 2.6x slower, and packing the shared-memory occlusion to 8 bits measured no change.
- Async compute made the frame slower, so it is not implemented. Light clustering and GTAO on a second graphics-family queue, alongside the shadow atlas and sky, took the GPU Trace frame from 3.29 to 6.93 ms, because that queue time-slices the graphics engine. On the dedicated compute family, which would also need queue-family ownership transfers that NVRHI does not perform, it took 5.0 ms: the compute work slowed to several times its serial cost while shading waited for it. With shadows and the tables cached, little independent raster work is left to hide compute behind. Revisit it when such work exists, for example cascades redrawn every frame of camera motion next to compute that does not need their result, and measure the whole frame the same way.
- Automatic exposure occupies one SM for about 0.03 ms. Spreading it across groups needs a second dispatch for the reduction, which costs a pipeline drain of its own.
- Each pass boundary still drains the pipe; merging passes that read the same inputs is the remaining lever. Folding the depth bounds reduction into the GTAO depth prefilter was considered and not done: that prefilter's 16x16-pixel groups would need about 45,000 atomic pairs on two addresses per frame at 3200x1809, and per-wave atomics at a similar scale measured 0.17 ms, more than the separate 0.036 ms pass that reduces 64x64-pixel blocks.

A per-tier GPU Trace on the same day, after the shadow work, found no pass running for a disabled feature: Low runs no GTAO, contact shadows, or soft shadow search, and Medium runs no contact shadows. The remaining clears are needed: depth before the prepass, and SMAA weights, which the indirect weight pass writes only at edge pixels. Two ranges looked expensive in the trace and were not: Low's sky read 0.95 ms because the editor UI's command list executed inside that range (19 draws and 4.7 million extra colour pixels against the sky's one triangle), and Medium's PBR range read 1.38 ms the same way; the renderer's own timestamps put them at 0.08 and 0.73 ms. Idle time in those traces is the visual test waiting on the editor's CPU frame. Bookmark averages at 3200x1809 are 1.32 ms on Low, 2.71 ms on Medium, and 3.48 ms on High, where contact shadows (0.23 ms) and percentage-closer soft shadows (about 0.06 ms) account for most of the rise since the tiers were introduced.

## Verification

`HertaTests` covers camera/picking and viewport input ownership, grouped authoring, graph/resource failure cleanup, renderer projection/winding, PBR material serialization and color-space/channel rules, normals/tangents, HDR environment filtering, light/shadow budgets, shader reflection and deterministic compilation, and shader snapshot coalescing with last-valid publication.

`HertaEditor --renderer-test` checks instanced versus single-draw GPU image equivalence, GPU image coverage, multi-section render meshes with per-section textures and uploaded mip chains, near-over-far depth occlusion, depth-tested and overlay debug primitives, point pixel size, recording cancellation, fence retirement, repeated offscreen resize/zero extents, and native resize/minimize/restore requests, then exits. It also locks the exposure calibration: an 18% grey, fully rough card under 100,000 lx of overhead sun at EV100 15 ("sunny 16") must display as neutral middle grey, between 98 and 116 in sRGB (it reads 107, because GT7 keeps the camera's 14.6% exposed grey nearly linear). The native resize sequence also switches panel blur between zero, normal, and maximum radius to exercise backdrop allocation and reuse. Where windows can be placed, which excludes Wayland, it then floats the Content Browser and Details panels, which show renderer thumbnails and previews, across the main window's edges so each gets its own native window and swapchain, resizes them, and resets the layout, requiring three platform windows while floating and one after. Development renderer tests require Vulkan validation instead of silently running without it. Smoke runs store layout and appearance under `TestResults/Smoke`.

`HertaEditor --visual-test --validation` renders the normal Sandbox playground and camera in a maximized window with the F11 full viewport, the most pixels a normal session renders, until 600 presented, asset-ready frames complete, then exits. It uses isolated layout/appearance settings rather than loading or writing personal preferences, and has a five-minute loading/presentation deadline. The log reports viewport size and total render-target bytes. It also reports the average wall time, CPU phases (render recording, swapchain acquire, ToolUI, and present), ToolUI GPU time, and GPU time for each visual pass over the last 599 frames. Single-frame GPU timings swing with clocks, so the averages are the numbers to compare. It then visits each of the level's camera bookmarks in slot order, lets each settle for 120 frames, meters auto exposure afresh 30 frames before the end because adaptation takes seconds, logs its GPU time averaged over the last 30 with the passes above 0.1 ms, heaviest first, its draw count, and with global illumination the irradiance field's probes traced, read by the camera, and found inside geometry, and saves the viewport, overlays included, to `Saved/VisualTest/00-Start.png` and `NN-<Bookmark name>.png`. This exercises the authored material/light/sky/fog/SMAA path; the images are for review, not a screenshot comparison, and do not replace checking appearance in the editor.

`--visual-test --resolution=WIDTHxHEIGHT` renders the viewport at a fixed size, up to 4096 per side, and shows it scaled to the panel, so timings compare across displays. In October 2026 on an RTX 4090 Laptop GPU at the High tier, the starting view measured GTAO at 0.11 ms at 1920x1080 (depth 0.02, occlusion 0.04, denoise 0.05) and 0.80 ms at 3840x2160 (0.12, 0.32, 0.38). SMAA High measured 0.42 ms at 3840x2160 (edges 0.26, weights 0.04, neighborhood 0.11) and 0.15 to 0.35 ms at 1920x1080: a 1080p frame leaves the GPU lightly loaded, and its clocks vary between runs. The nine bookmarks averaged 0.98 ms of GPU time at 1080p and 3.92 ms at 4K.
