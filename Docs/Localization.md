# Localization

Herta shows game and editor text in English, Polish, and Russian. Text is identified by stable keys, translated in canonical UTF-8 catalogs, formatted with ICU-style messages against CLDR culture data, and drawn through HarfBuzz shaping with font fallback.

## Modules

| Module | Kind | Owns |
| --- | --- | --- |
| `Localization` | Runtime | `FCulture` (CLDR plural rules, number and date formats), `FMessage` (message compilation and formatting), `FTextCatalog` parsing and canonical writing, `FLocalization` (fallback, pseudolocalization, generations). |
| `TextLayout` | Runtime | UTF-8 decoding, UAX #29 grapheme clusters, grapheme-aware editing, `FFontCollection` (HarfBuzz shaping with per-cluster font fallback, FreeType rasterization). HarfBuzz and FreeType stay private. |
| `LocalizationPipeline` | Developer | Catalog validation reports and generated text ID headers. |
| `EditorFramework` Localization panel | Editor | The LocalizationEditor: browsing, editing, validating, and saving translations. |

Culture data comes from a Herta-owned subset of CLDR 49 in `External/cldr/CldrData.h`, generated by `External/cldr/GenerateCldrData.py` for exactly the shipped cultures. Grapheme break properties come from the Unicode 17 database in `External/unicode/UnicodeData.h`. ICU4C is not used: the subset covers what the game needs, adds no binary data files, and keeps cooking deterministic. A culture is added by regenerating `CldrData.h` with it and translating its catalogs.

## Catalogs

Catalogs live at `<root>/<culture>/<Namespace>.hloc`:

- `Engine/Content/Localization` holds the `Game` namespace: the menus, HUD, controls, and notices from GameFramework. It is staged with every game.
- `Engine/Content/Editor/Localization` holds the `Editor` namespace. It never ships.

```json
{
  "format": "HertaTextCatalog",
  "version": 1,
  "culture": "pl",
  "namespace": "Game",
  "messages": [
    {"key": "Hud.FinishedSeconds", "text": "Ukończono w {seconds, plural, one {# sekundę} few {# sekundy} many {# sekund} other {# sekundy}}"}
  ]
}
```

`en` is the source culture and the only one whose messages carry a `comment` for translators. Messages are sorted by key, so a catalog writes the same bytes every time; `localization.validate` reports files that are not canonical. A translation may omit keys, which then fall back to the source; it may not add keys the source lacks or use different arguments.

## Messages

Messages use a subset of ICU MessageFormat with named arguments:

| Syntax | Meaning |
| --- | --- |
| `{name}` | A string, or a number in the culture's format. |
| `{name, number}`, `{name, number, integer}`, `{name, number, percent}` | Grouped decimals, whole numbers, or a fraction as a percentage. |
| `{name, date, short}` and `time`, `datetime` with `short`, `medium`, `long`, `full` | CLDR date and time patterns, with genitive month names inside dates. |
| `{name, plural, offset:1 =0 {...} one {# item} other {# items}}` | CLDR cardinal plural rules; `#` is the number less the offset. |
| `{name, select, ally {...} other {...}}` | Branches on a string. |

An apostrophe quotes `{`, `}`, and, in a plural, `#`; two apostrophes are one. Arguments are `std::int64_t`, `double`, `FFixedNumber`, `std::string`, or `FCivilTime`. `FFixedNumber` shows a fixed number of decimals and selects the plural form of the number as shown, so "1.00 seconds" stays plural in English while "1 second" is singular. A missing argument shows as `{name}`.

Never concatenate fragments of a sentence; give translators the whole message and let arguments and plural branches reorder.

## Text IDs

Code names messages through generated constants, not strings:

```cpp
#include "Herta/GameFramework/GameText.h"

Menu.ShowNotice(Text.Format(Text::Game::Notice_Saved));
```

`HertaEditorCmd localization.generate <source.hloc> <header.h>` writes the header, one `inline constexpr FTextId` per source key, whose 64-bit FNV-1a hash is computed at compile time. The generated headers are `Engine/Source/Runtime/GameFramework/Public/Herta/GameFramework/GameText.h` and `Engine/Source/Runtime/ToolUI/Public/Herta/ToolUI/EditorText.h`; a test fails when either is stale. Loading rejects two keys with the same hash.

## Runtime

`FLocalization::SetCatalogs` compiles every catalog into a new generation, or returns an error and keeps the previous one, so a broken translation never blanks the UI. Lookups fall back from the culture to its CLDR parent and then to the source; a key no catalog has shows itself. `GetGeneration` changes with the catalogs or the culture, for caches.

`qps-ploc` is pseudolocalization: the source text with accented letters, doubled vowels, and brackets, to find hard-coded strings and clipped layouts. It is offered in the game and editor language lists outside Shipping builds.

The game reads catalogs through its virtual file system, takes its culture from `culture=` in the per-user `Settings.ini` or from `--culture=<tag>`, and switches language live from Settings > Language. Every culture names itself in its own language in that list. Course times, volumes, and the save time in Load game format in the culture.

## Language packs

`HertaCooker cook --language-packs`, `PackageGame.ps1 -LanguagePacks`, or `PackageGame.sh --language-packs` keep translations out of the base package and write each as `<Project>-<culture>.hpak` beside it. The game mounts every package in its folder, so a pack adds its language and removing it leaves the source language. Packs are signed like the base package.

## Text display

GameUI shapes each string with HarfBuzz through `FFontCollection`. Each grapheme cluster uses the first font that has all of its characters: Roboto for Latin, Polish, and Cyrillic, then monochrome Noto Emoji. Glyphs rasterize on first use into 1024 px atlas pages; a page with new glyphs uploads as a fresh texture at the next frame boundary, so a glyph first drawn this frame shows from the next, and nothing rewrites a texture in flight. Printable ASCII is rasterized with the atlas so menus show on the first frame.

The editor merges Noto Emoji into its ImGui fonts and builds ImGui with 32-bit `ImWchar` so text past the Basic Multilingual Plane works. `ToolUIInputText` is a grapheme-aware text field: a code point deletion that cuts a cluster, such as an emoji's skin tone, widens to the whole cluster, and the cursor steps over clusters.

## Editor

The command palette and the Preferences, Project settings, and Plugins tabs take their text from the editor catalog. Short labels, such as panel names and every Details component, property, group, and option name, are looked up by their English text through `ToolUILabel`, under `Editor.Label.<letters and digits>`, and fall back to English when a catalog lacks them; a test checks every Details label has an entry. Edit > Preferences > Language switches the editor and editor Play between the loaded languages; the choice persists in the editor appearance file. Tools > Localization opens the translation editor: pick a translation, search keys and text, filter to untranslated messages, and edit translations with live validation and a preview formatted with sample arguments. Save writes canonical catalogs atomically. The editor polls the catalog folders once a second and reloads on any change, including edits made outside it; a catalog that fails to load keeps the previous text and logs why.

`HertaEditorCmd localization.validate` checks both catalog roots and lists errors, untranslated messages, and non-canonical files; staging refuses catalogs that do not load.

## Limits

- Left-to-right text only. Right-to-left scripts shape but keep logical order; BiDi, Indic, and CJK acceptance are later work.
- Key and button names in bindings are device labels and stay in English.
- Panel titles stay English, because ImGui uses them as layout identities.
- Emoji are monochrome and tinted by the text color.
- Shaping and rasterization run on the UI thread; they cost microseconds for the HUD's strings. Moving rasterization to workers waits for text heavy enough to show in a profile.
- Cooked catalogs are canonical JSON rather than a binary format; they are a few kilobytes each.
- The game's first language is English rather than the operating system's.
- XLIFF interchange waits for a translator workflow that needs it.
- Projects cannot localize yet. Catalogs load, stage, and cook only from the engine roots, and the translation editor offers only the `Game` and `Editor` namespaces. The planned order: project catalogs under `<Project>/Content/Localization` in a namespace named after the project, loaded beside `Game`, staged, cooked into language packs, edited in the translation editor, and given a text ID header in the game module; then a text property type that stores a catalog key for strings authored in levels and graphs, with a command that gathers them; then mod catalogs layered like mod content.
