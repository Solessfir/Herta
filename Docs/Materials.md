# Materials

Materials are stable-ID `.hmat` assets containing canonical, versioned JSON. Mesh geometry is shared independently of material assignments. Imported glTF materials remain the default for each section; a level's Static Mesh component can override individual slots with material asset IDs.

## Authoring

Right-click a Game folder in the Content Browser and choose **New material**. Double-click a material to open its editor. Assign it through a Static Mesh slot in Details, or drag it onto a viewport mesh to assign slot zero. Engine materials are read-only.

The material editor provides tint, metallic, roughness, diffuse roughness, a metal edge color, normal strength, occlusion strength, emissive color/intensity, UV scale/offset, and Opaque/Masked settings. Each texture binding has an explicit channel and color space. Base color and emissive normally use sRGB; normal, metallic, roughness, and occlusion use Linear. Packed maps can reuse one texture with different channels, such as R for occlusion, G for roughness, and B for metallic.

Diffuse roughness selects EON rough diffuse, which keeps the authored color's average reflectance while flattening shading towards silhouettes; 0, the default, is Lambert, which suits stylized content that wants clean shape shading while keeping GGX highlights. Edge color is OpenPBR's `specular_color` for metals: the reflectance near 82 degrees becomes that color times Schlick's, through F82-tint Fresnel, and white is plain Schlick. The editor shows it only for metallic materials. Material version 2 stores both as `diffuseRoughness` and `specularColor`; version 1 files load with their defaults. Version 3 adds `graphParameters`, and saving writes version 3.

HDR textures store linear floating-point radiance and require Linear bindings, including base color and emissive. An sRGB HDR binding reports an error rather than silently changing its interpretation.

Changes preview on a studio-lit sphere without saving source files, using the HDR PBR, environment, tone-map, and SMAA path. Parameter-only changes reuse GPU textures; texture changes cook asynchronously. Shader publication refreshes previews from cached materials without recooking their textures. Save commits the asset atomically. Reload, closing a dirty editor, changing projects, and exiting prompt with Save, Discard, or Cancel. Ctrl+Z and redo operate on the focused material editor's own bounded history; level slot assignments use level history.

Missing or failed textures and shader updates retain the last valid preview and report an actionable error. Masked materials clip against the authored alpha cutoff in both surface and shadow passes. Transparent blending is not implemented.

## Shader iteration

An empty shader path uses `Engine/Shaders/TexturedMesh.slang`. A nonempty portable `.slang` or `.hmatgraph` path is relative to the material's own content mount. Prefix it with `Game/` or `Engine/` to select that content mount explicitly, including cross-mount references. These prefixes select content roots, not `Engine/Shaders`; include `VisualShared.slangh` from the separate engine shader include root, and `VisualLights.slangh` to read lights and their cluster masks; the uniform block no longer carries lights. Headless cooks provide explicit Engine/Game roots to resolve mounted paths, and use the requested content root as Game when no separate Game root is configured.

- Entry points: `vertexMain`, `instancedVertexMain`, and `fragmentMain` for shading, the depth prepass variants `depthFragmentMain`, `velocityFragmentMain`, `instancedVelocityVertexMain`, `surfaceFragmentMain`, and `velocitySurfaceFragmentMain`, the ray-traced bake `bakeVertexMain`, `bakeSurfaceFragmentMain`, and `bakeLightFragmentMain`, and the masked shadow cutout `shadowFragmentMain`. Including `MeshShading.slangh` provides all of the prepass, bake, and shadow variants; they cut out by `EvaluateMaterial`'s alpha and write its normal and roughness for global illumination, so a custom shader only defines `EvaluateMaterial`. Custom shaders draw their own depth prepass, and their shading tests against that depth without writing it, like the engine material.
- Vertex data: position, UV, normal, and tangent with handedness; instancing carries object-to-clip and object-to-view matrices. The velocity prepass also binds the previous object-to-clip matrix as a second instance stream.
- Bindings: six material textures at t0-t5, diffuse/specular environment at t6-t7, shadow atlas at t8, rect light LTC tables at t9-t10, screen occlusion at t11, the GGX specular albedo table at t12, lights and their cluster masks at t16-t17, `FVisualUniforms` at Vulkan binding 64, linear sampler at 128, and the existing 128-byte push constant layout. Every entry point must reflect the exact current `FVisualUniforms` byte size; smaller, larger, or missing buffers are rejected before publication.

The editor watches source and literal includes/imports on background tasks. All twelve stages compile side by side, one `HertaShaderWorker` process each, from the same immutable source snapshot; GraphStripes compiles in about 1 s. The engine material defines `HERTA_ENGINE_MATERIAL` before including `MeshShading.slangh`, which keeps its prepass on texture reads alone: Slang keeps the unused samples of a whole `DefaultMaterial`, which would double its velocity prepass to 2742 words. Compatible pipelines publish together; errors retain the last valid pipeline and appear beside the shader path and in the Output Log. The snapshot directory is named by the source key because the worker embeds its paths as debug info: identical sources then produce identical SPIR-V, the driver's pipeline cache hits, and publishing a material's shading and prepass pipelines takes about 13 ms instead of 1.2 s (35 to 40 ms on a cold driver cache, both measured under validation by `--renderer-test`). Pipelines are still created on the main thread, so the first publish after a source change stalls for that compile; moving creation to a worker needs thread-safe pipeline creation in the RHI. Shader compilation is developer-only, not a runtime or Shipping dependency. The experimental Shipping editor disables shader iteration and uses engine PBR for custom-shader materials. Packaged games load custom shaders precompiled by `game.stage`; see [Game.md](Game.md).

Changing the uniform ABI requires updating both the C++ and Slang definitions and recooking every affected shader.

## Material Graphs

A material whose shader path names a `.hmatgraph` file is shaded by a Material Graph. **Create graph** in the material's Shader section writes `<material>.hmatgraph` beside a Game material, starting from the base color texture feeding the output, and opens it; **Edit graph** opens an existing one, as does passing the file to the editor on its command line. Passing a `.hmat` opens that material the same way.

### Material instances

Scalar Parameter and Vector Parameter nodes give a graph named inputs with defaults. Each `.hmat` that uses the graph is an instance of it: the Material panel lists the graph's parameters first, under Graph parameters, and a value set there is saved in the material's `graphParameters` by name, with the reset button removing it so the graph's default applies again. Names use letters, digits, and underscores, start with a letter, and are at most 32 long; a graph has at most 8 parameters, and two parameters cannot share a name. Texture parameters are the material's six texture slots, which Texture Sample nodes already read.

Static Switch nodes choose between their True and False inputs when the shader compiles, by name with a default, under the same naming rules; a graph has at most 8. Materials set them in `staticSwitches`, shown as checkboxes above the parameters. Each combination a material sets is a separate shader, named by appending the values to the shader key, as in `Game/Master.hmatgraph#Horizontal=1`; that key flows through the shader watcher, `game.stage`, `material.compile`, and the renderer unchanged, so a permutation compiles only when some material uses it, and the branch left out costs nothing at run time. The branch a switch leaves out still counts as connected, so it raises no warning. Switch values on a hand-written shader are ignored.

Parameters occupy the 8 float4 `MaterialParameters` slots of the visual uniforms, which grow every draw's uniforms by 128 bytes. The compiler assigns slots in name order and reports the parameter table; values are stored by name, so adding, removing, or reordering parameters never moves a material's values to another parameter, and a value whose parameter was renamed away is kept until it is renamed back. Published shaders carry their table, and each draw merges the material's sorted values with it in one pass. `game.stage` and `material.compile` write the table beside the cooked stages as `<shader>.parameters`. Parameters live outside `FMaterialUniform`, which ray-traced scene records embed.

### Ray-traced hits

Global illumination and the path tracer evaluate materials inline from ray queries, so they cannot run a custom shader at a hit. Instead each custom-shader material is baked when the renderer traces rays: two draws of a clip-space quad run the shader's `bakeSurfaceFragmentMain` and `bakeLightFragmentMain`, which call its own `EvaluateMaterial` over the UV square, into four 128x128 Rgba16Float textures holding base color and alpha, metallic-roughness-occlusion, emissive, and the tangent-space normal (the tangent frame is identity during the bake). The material's ray-traced record then points at those textures with unit factors, so `RayTracing.slangh` reads graph and engine materials the same way. A bake is redone only when the material changes (each `FRenderMaterial` carries a serial) or a shader publishes, and dropped when the material is no longer drawn. The reduction: graphs that read world position see the UV at z 0, and UVs outside the unit square wrap. Masked custom materials cast shadows through `shadowFragmentMain`, which evaluates their alpha the same reduced way behind Shadow.slang's vertex stages, and shadow tiles redraw when such a material or any shader changes; opaque custom materials keep the engine's shadow shader. `HertaEditor --renderer-test` path traces the parity cube with the graph and the engine material and requires a mean channel difference of at most 1; it measures 0.2, and 37 with the bake disabled.

The graph editor pans with the middle or right mouse button and zooms with the wheel about the cursor. A right click on empty canvas opens a searchable node menu; dragging between pins connects them, replacing whatever fed the input. Ctrl+drag lifts a pin's links and carries them to another pin: an input's link by its end, an output's links all together. Dropping a wire on empty canvas opens the node menu there and connects the node it places, and closing the menu removes lifted links. Alt+click breaks a pin's links or removes the link under the cursor. Click, Ctrl or Shift+click, and box selection select nodes, which move by dragging in 16-unit grid steps, duplicate with Ctrl+D, and delete with Delete. F formats the trees the selection belongs to, or the whole graph with nothing selected: every node moves into a column left of all its consumers, aligned so its output runs straight into the first input it feeds, without overlaps. Q straightens each selected node's link, Shift+W, S, A, and D align the selection's top, bottom, left, and right edges, and the node menu adds middle and center alignment and even horizontal or vertical distribution. With one node selected, the arrow keys select the nearest node in that direction and Alt+arrow swaps places with it; Tab and Shift+Tab walk its pins, Enter follows the pin's link to the node at the other end, and Alt+Up or Down swaps an input's link with the input above or below. The node menu swaps two selected nodes. Z frames the trees the selection belongs to. Ctrl+C, Ctrl+X, and Ctrl+V copy, cut, and paste nodes as graph text at the cursor; Shift+Delete and Ctrl+Shift+X delete or cut while bridging the gap, so what fed a removed node's first connected input feeds its consumers. Dragging a lone node without links onto a link inserts it there. Double-clicking a link adds a reroute knot, which compiles to its input and also comes from the node menu. C wraps the selection in a comment, or drops one at the cursor; dragging a comment's title bar moves it with the nodes inside, its corner grip resizes it, and double-clicking the title renames it. Comments are saved in graph format version 2; version 1 files still load. The side panel left of the canvas shows the graph's material on the studio sphere, refreshed each time the graph recompiles, and the mouse wheel over it zooms the Material and Material Graph previews alike; the material is the `.hmat` beside the graph that uses it. Below it, the side panel edits the selected node's properties and lists compile errors and warnings; clicking one selects its node. Edits undo and redo with Ctrl+Z and Ctrl+Y and save with Ctrl+S. Closing the editor or switching projects with unsaved graph edits asks to save first.

Graphs are typed by vector width. Values, inputs (texture coordinate, world position, vertex normal), texture samples of the material's six slots, math, channel split and combine, and the Material Output make up the first node set; math nodes take any width and widen scalars, and mismatched widths are errors on the node that combines them. The compiler walks back from the output, so unconnected nodes are warnings rather than code; it folds constants and merges identical expressions, then generates one `EvaluateMaterial` function that includes `GraphMaterial.slangh`. Outputs the graph leaves unconnected keep the material asset's own parameters and textures, so a graph only replaces what it connects; a graph normal is tangent space, like a normal map.

Graphs compile through the material shader watcher like hand-written shaders and keep the last valid pipeline on failure. While a graph has unsaved edits, the watcher compiles the editor's draft instead of the file, at once rather than at its next poll, so the preview and every material using the graph show each edit live, including during a property drag, which cancels compiles it has overtaken. Saving keeps the draft's pipeline, since the file then compiles to the same source; closing without saving compiles the file again. `game.stage` compiles them with the same code as the editor and ships the SPIR-V, and `HertaEditorCmd material.compile Game/<path> <output> [--content-root <path>]` does the same for one shader. `HertaEditor --renderer-test` builds a graph that rebuilds the engine material (base color texture times a tint, constant metallic and roughness), compiles it headless, and requires identical pixels to the engine material with the same parameters on a cube above a floor with ambient occlusion, which reads the depth prepass. Each side renders in a fresh renderer, and the sun casts no shadow maps, because their cascades fit depth bounds read back a few frames late and so change with GPU timing.
