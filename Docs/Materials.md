# Materials

Materials are stable-ID `.hmat` assets containing canonical, versioned JSON. Mesh geometry is shared independently of material assignments. Imported glTF materials remain the default for each section; a level's Static Mesh component can override individual slots with material asset IDs.

## Authoring

Right-click a Game folder in the Content Browser and choose **New material**. Double-click a material to open its editor. Assign it through a Static Mesh slot in Details, or drag it onto a viewport mesh to assign slot zero. Engine materials are read-only.

The material editor provides tint, metallic, roughness, diffuse roughness, a metal edge color, normal strength, occlusion strength, emissive color/intensity, UV scale/offset, and Opaque/Masked settings. Each texture binding has an explicit channel and color space. Base color and emissive normally use sRGB; normal, metallic, roughness, and occlusion use Linear. Packed maps can reuse one texture with different channels, such as R for occlusion, G for roughness, and B for metallic.

Diffuse roughness selects EON rough diffuse, which keeps the authored color's average reflectance while flattening shading towards silhouettes; 0, the default, is Lambert, which suits stylized content that wants clean shape shading while keeping GGX highlights. Edge color is OpenPBR's `specular_color` for metals: the reflectance near 82 degrees becomes that color times Schlick's, through F82-tint Fresnel, and white is plain Schlick. The editor shows it only for metallic materials. Material version 2 stores both as `diffuseRoughness` and `specularColor`; version 1 files load with their defaults, and saving writes version 2.

HDR textures store linear floating-point radiance and require Linear bindings, including base color and emissive. An sRGB HDR binding reports an error rather than silently changing its interpretation.

Changes preview on a studio-lit sphere without saving source files, using the HDR PBR, environment, tone-map, and SMAA path. Parameter-only changes reuse GPU textures; texture changes cook asynchronously. Shader publication refreshes previews from cached materials without recooking their textures. Save commits the asset atomically. Reload, closing a dirty editor, changing projects, and exiting prompt with Save, Discard, or Cancel. Ctrl+Z and redo operate on the focused material editor's own bounded history; level slot assignments use level history.

Missing or failed textures and shader updates retain the last valid preview and report an actionable error. Masked materials clip against the authored alpha cutoff in both surface and shadow passes. Transparent blending is not implemented.

## Shader iteration

An empty shader path uses `Engine/Shaders/TexturedMesh.slang`. A nonempty portable `.slang` or `.hmatgraph` path is relative to the material's own content mount. Prefix it with `Game/` or `Engine/` to select that content mount explicitly, including cross-mount references. These prefixes select content roots, not `Engine/Shaders`; include `VisualShared.slangh` from the separate engine shader include root, and `VisualLights.slangh` to read lights and their cluster masks; the uniform block no longer carries lights. Headless cooks provide explicit Engine/Game roots to resolve mounted paths, and use the requested content root as Game when no separate Game root is configured.

- Entry points: `vertexMain`, `instancedVertexMain`, and `fragmentMain`.
- Vertex data: position, UV, normal, and tangent with handedness; instancing carries object-to-clip and object-to-view matrices. Custom shaders skip the depth prepass, so they never read the previous object-to-clip matrix, which only the engine's velocity prepass binds as a second instance stream.
- Bindings: six material textures at t0-t5, diffuse/specular environment at t6-t7, shadow atlas at t8, rect light LTC tables at t9-t10, screen occlusion at t11, the GGX specular albedo table at t12, lights and their cluster masks at t16-t17, `FVisualUniforms` at Vulkan binding 64, linear sampler at 128, and the existing 128-byte push constant layout. Every entry point must reflect the exact current `FVisualUniforms` byte size; smaller, larger, or missing buffers are rejected before publication.

The editor watches source and literal includes/imports on background tasks. All three stages compile from the same immutable source snapshot through `HertaShaderWorker`. Compatible pipelines publish together; errors retain the last valid pipeline and appear beside the shader path and in the Output Log. The snapshot directory is named by the source key because the worker embeds its paths as debug info: identical sources then produce identical SPIR-V, the driver's pipeline cache hits, and publishing a material's two pipelines takes about 16 ms instead of 1.2 s. Pipelines are still created on the main thread, so the first publish after a source change stalls for that compile; moving creation to a worker needs thread-safe pipeline creation in the RHI. Shader compilation is developer-only, not a runtime or Shipping dependency. The experimental Shipping editor disables shader iteration and uses engine PBR for custom-shader materials; portable custom-shader deployment belongs to the standalone runtime's cooking/deployment slice.

Changing the uniform ABI requires updating both the C++ and Slang definitions and recooking every affected shader.

## Material Graphs

A material whose shader path names a `.hmatgraph` file is shaded by a Material Graph. **Create graph** in the material's Shader section writes `<material>.hmatgraph` beside a Game material, starting from the base color texture feeding the output, and opens it; **Edit graph** opens an existing one, as does passing the file to the editor on its command line.

The graph editor pans with the middle or right mouse button and zooms with the wheel about the cursor. A right click on empty canvas opens a searchable node menu; dragging between pins connects them, dragging from a connected input picks its link up, and dropping it on nothing removes it; Alt+click also removes a link. Click, Ctrl or Shift+click, and box selection select nodes, which move by dragging in 16-unit grid steps, duplicate with Ctrl+D, and delete with Delete. F formats the trees the selection belongs to, or the whole graph with nothing selected: every node moves into a column left of all its consumers, aligned so its output runs straight into the first input it feeds, without overlaps. Q straightens each selected node's link, Shift+W, S, A, and D align the selection's top, bottom, left, and right edges, and the node menu adds middle and center alignment and even horizontal or vertical distribution. With one node selected, the arrow keys select the nearest node in that direction and Alt+arrow swaps places with it; Tab and Shift+Tab walk its pins, Enter follows the pin's link to the node at the other end, and Alt+Up or Down swaps an input's link with the input above or below. The node menu swaps two selected nodes. Z frames the trees the selection belongs to. Ctrl+C, Ctrl+X, and Ctrl+V copy, cut, and paste nodes as graph text at the cursor; Shift+Delete and Ctrl+Shift+X delete or cut while bridging the gap, so what fed a removed node's first connected input feeds its consumers. Dragging a lone node without links onto a link inserts it there. Double-clicking a link adds a reroute knot, which compiles to its input and also comes from the node menu. C wraps the selection in a comment, or drops one at the cursor; dragging a comment's title bar moves it with the nodes inside, its corner grip resizes it, and double-clicking the title renames it. Comments are saved in graph format version 2; version 1 files still load. The side panel edits the selected node's properties and lists compile errors and warnings; clicking one selects its node. Edits undo and redo with Ctrl+Z and Ctrl+Y and save with Ctrl+S. Closing the editor or switching projects with unsaved graph edits asks to save first.

Graphs are typed by vector width. Values, inputs (texture coordinate, world position, vertex normal), texture samples of the material's six slots, math, channel split and combine, and the Material Output make up the first node set; math nodes take any width and widen scalars, and mismatched widths are errors on the node that combines them. The compiler walks back from the output, so unconnected nodes are warnings rather than code; it folds constants and merges identical expressions, then generates one `EvaluateMaterial` function that includes `GraphMaterial.slangh`. Outputs the graph leaves unconnected keep the material asset's own parameters and textures, so a graph only replaces what it connects; a graph normal is tangent space, like a normal map.

Saved graphs compile through the material shader watcher like hand-written shaders and keep the last valid pipeline on failure. Like other custom shaders, graph materials skip the depth prepass and are not yet staged into packaged games.
